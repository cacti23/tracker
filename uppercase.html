// your interview brain OS

U
UNDERSTAND before touching code
Restate the problem in your own words. Clarify input/output. Ask about constraints. Confirm: sorted? distinct values? negative numbers? what's n?
"So if I understand correctly, we need to find X given Y, and the constraints are Z — is that right?"
⏱ SPEND 2–3 MIN HERE. NON-NEGOTIABLE.
P
PATTERN — fire your detector
Scan trigger keywords. Match data shape + constraint type to a known pattern. Say it out loud. If nothing fires, go brute force first.
"This smells like [pattern] because I see [keyword] and the constraint is [X]."
⏱ 1–2 MIN. PATTERN FIRST, CODE NEVER FIRST.
E
EXAMPLES — trace before coding
Manually trace 2–3 examples on paper/whiteboard. Include at least one edge case. The algorithm usually reveals itself here.
Run: normal case → edge case (empty / single / all-same) → large n mentally
⏱ 2–3 MIN. THIS IS WHERE BUGS DIE.
R
RECITE brute force first
Always verbalize the naive solution. State its complexity. Then ask: "can we do better?" This shows depth — you understand WHY the optimal works.
"Brute force: [approach] → O(n²) time. Bottleneck is [X]. Can we eliminate it with [pattern]?"
⏱ 30 SEC. NEVER SKIP THIS NARRATION.
A
ASK: what's the bottleneck?
Locate repeated work. Ask: can I cache this? (DP/Memo) Can I binary search this? Can I maintain a sorted structure? Can I use a running variable?
"The bottleneck is recomputing [X] — if I store it in [structure], I get O(1) per step."
⏱ THIS QUESTION ALONE UNLOCKS 80% OF OPTIMIZATIONS.
C
CODE with live narration
Talk every line. Name variables meaningfully. No silence. Interviewer grades communication equally as code. Write clean, modular code.
"I'm using a hashmap here for O(1) lookup... left pointer starts at 0... I shrink when condition breaks..."
⏱ SILENCE = RED FLAG. NEVER GO QUIET.
S
SCAN edge cases — before "done"
Run the checklist out loud. Proactively catch bugs. State your fix.
[] empty input
n=1 single
all duplicates
negatives
INT overflow
already sorted
off-by-one
null pointer
⏱ 1–2 MIN. CATCH BEFORE THEY DO.
E
EXPLAIN complexity + tradeoffs
State time + space. Mention tradeoffs. Offer alternative if interviewer probes. Show you can think beyond the solution.
"Time: O(n log k), Space: O(k). If memory is a constraint, we could [alternative]."
⏱ THIS GETS YOU TO SDE3. MOST STOP AFTER CODE.
