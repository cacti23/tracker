// 6-step problem-solving loop

U
UNDERSTAND the problem
Restate it in your own words. Lock down input/output, constraints, and n (sorted? distinct? negatives?). Run one normal + one edge example by hand.
"So we need X given Y, constraints are Z — and for input [..] the answer is [..], right?"
⏱ 2–3 MIN. NON-NEGOTIABLE.
M
MATCH a pattern
Map keywords + data shape to a known pattern (cards on the right). Say it out loud. If nothing fires, brute force first — that's fine.
"This smells like [pattern] because I see [keyword] and the constraint is [X]."
⏱ 1–2 MIN. PATTERN FIRST, CODE NEVER FIRST.
P
PLAN — brute force, then the bottleneck
State the brute force + its complexity, then ask the unlock question: "where is the repeated work?" Cache it, sort it, two-pointer it, or keep a running structure.
"Brute force is O(n²); the bottleneck is recomputing [X]. If I store it in [structure], each step is O(1)."
⏱ 1–2 MIN. NEVER SKIP THE BRUTE-FORCE NARRATION.
I
IMPLEMENT with live narration
Code it cleanly, narrating every line. Meaningful names, small helpers. Communication is graded as heavily as the code.
"Hashmap here for O(1) lookup... left pointer at 0... I shrink the window when the condition breaks..."
⏱ SILENCE = RED FLAG. NEVER GO QUIET.
R
REVIEW — trace + edge cases
Re-trace your code on an example as if you were the interviewer. Walk each edge case below — catch bugs before they run it.
[] empty input
n=1 single
all duplicates
negatives
INT overflow
already sorted
off-by-one
null pointer
"Tracing [example]... edge cases hold, no off-by-one at the boundary."
⏱ 1–2 MIN. CATCHES BUGS BEFORE THEY RUN IT.
E
EVALUATE — complexity + tradeoffs
State final time and space. Name the tradeoff and how you'd adapt if a constraint changed (bigger n, streaming, no extra space). This is the SDE3 signal.
"Time O(n log k), space O(k). If [constraint] changed, I'd switch to [alternative]."
⏱ 1 MIN. THE SDE3 SIGNAL — NEVER SKIP IT.
