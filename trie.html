🧠 1 · How to think (and invent it)

A trie stores strings by their shared prefixes. Each node owns a map of child characters; walking a word's letters from the root traces (or builds) a path, and a boolean isEnd flags where real words finish. Every operation — insert, search, prefix-check — is one walk down the word: O(L), completely independent of how many words are stored.

Watch it get invented — a prefix-searchable dictionary

  1. Start with a hash set. It answers "is X a word?" in O(L) — but "is X a prefix of some word?" forces a scan of every entry: O(N·L).
  2. The leap. Words that share a prefix should share storage. Lay them in a tree keyed by character; common prefixes become a single shared path that branches only where the words diverge.
  3. The two queries fall out. search(w) = walk w; it's a word iff the path exists and ends on isEnd. startsWith(p) = walk p; true iff the path exists at all.
  4. Payoff. O(L) per op regardless of N, and prefixes are stored once.
When a trie beats a hash set Use a trie for prefix work (autocomplete, "starts with", longest common prefix) and as a pruner for searches (only explore paths that are valid prefixes). If you only need exact membership, a hash set is simpler, as fast, and lighter.

🧩 4 · The five core patterns

Node throughout: { children: Map<char, Node>, isEnd: boolean }. Each pattern: a one-liner, a 🔑 invariant, a template, a 🎤 interview lens.

4.1 · Mechanics — insert / search / startsWith

“Walk the word; create missing children on insert, follow them on lookup.”

🔑 Invariant — why it's safe After inserting a word, exactly one root-to-node path spells it and that final node has isEnd = true. So a lookup that follows the same characters lands on that node iff the word was inserted — and isEnd distinguishes a stored word from a mere prefix.
class TrieNode { children = new Map<string, TrieNode>(); isEnd = false; }

class Trie {
  root = new TrieNode();
  insert(word: string): void {
    let node = this.root;
    for (const c of word) {
      if (!node.children.has(c)) node.children.set(c, new TrieNode());
      node = node.children.get(c)!;
    }
    node.isEnd = true;
  }
  private walk(s: string): TrieNode | null {
    let node = this.root;
    for (const c of s) { const next = node.children.get(c); if (!next) return null; node = next; }
    return node;
  }
  search(word: string): boolean { const n = this.walk(word); return !!n && n.isEnd; }
  startsWith(prefix: string): boolean { return this.walk(prefix) !== null; }
}
🎤 Interview lens Probed: the node shape (Map vs 26-array trade-off), why ops are O(L) regardless of N, and the isEnd distinction. · Escalation: implement → add delete → store a count of words passing through each node.

4.2 · Prefix queries — autocomplete

“Walk to the prefix node, then DFS everything beneath it.”

Setup: the subtree rooted at the prefix node contains exactly the words sharing that prefix — collect them with a DFS.

🔑 Invariant — why it's safe Reaching the prefix node means the prefix exists. Every isEnd in that subtree is a stored word whose first letters are exactly the prefix (that's how it got placed there) — so the DFS collects all completions and nothing else.
// All stored words that start with `prefix`
function wordsWithPrefix(trie: Trie, prefix: string): string[] {
  const start = (trie as any).walk(prefix) as TrieNode | null;
  if (!start) return [];
  const out: string[] = [];
  (function dfs(node: TrieNode, suffix: string) {
    if (node.isEnd) out.push(prefix + suffix);
    for (const [c, child] of node.children) dfs(child, suffix + c);
  })(start, '');
  return out;
}
🎤 Interview lens Probed: walk-then-DFS, and lexicographic order (iterate children sorted). · Escalation: words-with-prefix → top-k autocomplete (store frequencies) → "Replace Words" (shortest root) → "Map Sum Pairs" (prefix value sums).

4.3 · Wildcard search (. matches any)

“On a literal, follow one child; on a dot, try them all.”

Setup: a normal walk can't handle . because it could match several children — so the walk becomes a branching DFS that recurses into every child whenever it sees a dot.

🔑 Invariant — why it's safe dfs(node, i) returns true iff the word's suffix from index i can be matched starting at node. A literal advances one definite child; a . succeeds iff any child can match the rest — exhaustive over the only possibilities.
// Add and Search Word — '.' matches any single character
search(word: string): boolean {
  const dfs = (node: TrieNode, i: number): boolean => {
    if (i === word.length) return node.isEnd;
    const c = word[i];
    if (c === '.') {
      for (const child of node.children.values()) if (dfs(child, i + 1)) return true;
      return false;
    }
    const next = node.children.get(c);
    return next ? dfs(next, i + 1) : false;
  };
  return dfs(this.root, 0);
}
🎤 Interview lens Probed: branching only on .; worst-case cost when dots are early/many. · Escalation: single . → multiple wildcards → regex-style *.

4.4 · Trie as a pruner (grid / word break)

“Drive one DFS by the trie — abandon any path that isn't a live prefix.”

Setup: instead of searching the grid once per word, build a trie of all words and run a single DFS; at each cell, only continue if the trie has that character as a child. The trie collapses many searches into one and prunes dead ends instantly.

🔑 Invariant — why it's safe The DFS holds a trie node that always corresponds to the string spelled by the current grid path. If the next cell's letter isn't a child of that node, no dictionary word continues this way — so the whole branch is pruned. A node's word field firing means a complete dictionary word ends here.
// Word Search II — all dictionary words found in the board
function findWords(board: string[][], words: string[]): string[] {
  const root = new TrieNode() as TrieNode & { word?: string };
  for (const w of words) {                      // build the trie, tag ends with the full word
    let n: any = root;
    for (const c of w) { if (!n.children.has(c)) n.children.set(c, new TrieNode()); n = n.children.get(c); }
    n.word = w;
  }
  const out: string[] = [], R = board.length, C = board[0].length;
  function dfs(r: number, c: number, node: any) {
    const ch = board[r][c], child = node.children.get(ch);
    if (!child) return;                          // PRUNE: not a live prefix
    if (child.word) { out.push(child.word); child.word = undefined; } // collect + dedup
    board[r][c] = '#';                           // mark visited
    for (const [dr, dc] of [[0,1],[0,-1],[1,0],[-1,0]]) {
      const nr = r + dr, nc = c + dc;
      if (nr >= 0 && nr < R && nc >= 0 && nc < C && board[nr][nc] !== '#') dfs(nr, nc, child);
    }
    board[r][c] = ch;                            // restore (backtrack)
  }
  for (let r = 0; r < R; r++) for (let c = 0; c < C; c++) dfs(r, c, root);
  return out;
}
🎤 Interview lens Probed: building the trie of words, pruning by trie children, plus dedup and board restore (backtracking). · Escalation: Word Search II → "Concatenated Words" → "Word Break II" (trie + memo).

4.5 · Bit trie — XOR greedily

“Store numbers as bit-paths; to maximize XOR, walk choosing the opposite bit.”

Setup: insert each number's bits MSB→LSB into a binary trie. To maximize a XOR b, for each a walk the trie always preferring the opposite bit (which sets that XOR bit to 1) when it exists.

🔑 Invariant — why greedy is optimal XOR is maximized bit by bit from the MSB: a 1 in a higher bit outweighs all lower bits combined. So at each level, if the opposite-bit branch exists, taking it is strictly best — no later choice can recover a higher bit you passed up.
// Maximum XOR of Two Numbers in an array (30-bit ints)
function findMaximumXOR(nums: number[]): number {
  const root: any = {};
  for (const num of nums) {                    // insert bits MSB → LSB
    let node = root;
    for (let b = 30; b >= 0; b--) { const bit = (num >> b) & 1; node = node[bit] ??= {}; }
  }
  let best = 0;
  for (const num of nums) {
    let node = root, cur = 0;
    for (let b = 30; b >= 0; b--) {
      const bit = (num >> b) & 1, want = bit ^ 1;   // greedily seek the opposite bit
      if (node[want]) { cur |= (1 << b); node = node[want]; }
      else node = node[bit];
    }
    best = Math.max(best, cur);
  }
  return best;
}
🎤 Interview lens Probed: MSB-first insertion, the greedy opposite-bit walk, and O(n · bits). · Escalation: max XOR → "Count Pairs With XOR in a Range" → "Maximum XOR With an Element From Array" (offline + sort).

The size-independence insight A trie's per-word cost depends on the word's length, never on the dictionary size — that's its superpower over scanning. Its weakness is memory: many sparse nodes; a Map keeps them lean.
