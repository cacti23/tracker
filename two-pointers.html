🧠 1 · How to think (and invent it)

The one idea: instead of checking every pair with two nested loops (O(n²)), keep two indices that each move in one direction only, never backtracking. Each pointer crosses the array at most once, so the whole scan is O(n).

The craft is choosing a rule for which pointer to move such that you provably never skip a valid answer. That rule is always justified by an invariant — a fact that stays true on every step. Learn to name the invariant and the code falls out.

Mental checklist Before coding, answer three things: (1) where do the pointers start? (2) what moves each one (the rule)? (3) when do you stop? If you can state the invariant that makes the move-rule safe, you're done thinking.

Watch it get invented — Two Sum II

Sorted array, find two values summing to target. Don't memorize the trick — derive it, because that's the skill that transfers.

  1. Start brute. Try every pair → O(n²). On [2,7,11,15], target 18: test (2,7), (2,11), (2,15), (7,11)…
  2. Spot the waste. Testing (2, 15) = 17 < 18 tells you something huge: 2 paired with the largest value available is still too small — so 2 can't reach 18 with anything. 2 is dead. Brute force ignores that and keeps re-testing it.
  3. The leap. Put one pointer at each end. Now the sum names the culprit for you: too small ⇒ the left value is the ceiling on this pair, advance it; too big ⇒ the right value is the floor, retreat it.
  4. Payoff. Every step permanently eliminates one element ⇒ ≤ n steps ⇒ O(n), O(1) space.

Trace it once by hand and it's yours forever:

stepLRa[L] + a[R]vs 18action

First reflex If the prompt screams "pairs that sum/compare" and order doesn't matter, sort first (O(n log n)) — sorting is what unlocks the converging rule. Only skip it if you need original indices (then a hash map beats it).
When two pointers is the WRONG tool · You need the original indices of an unsorted array — sorting destroys them; use a one-pass hash map.
· You must count every qualifying pair, not just find one — the converging sweep skips pairs by design, so it undercounts.
· The compare-and-move decision isn't monotonic (moving a pointer doesn't reliably head toward the answer) — the safety proof collapses.
· The data can't be sorted and order carries meaning — usually that's a sliding window or a map, not this.

🧩 4 · The four core patterns

Each pattern below = a one-line mental model, a 🔑 invariant (the proof it's correct), a template, a picture, and a 🎤 interview lens (what's probed + the next escalation).

4.1 · Converging — opposite ends, move inward

“Squeeze from both ends; drop the loser.”

Setup: sorted array, L=0, R=n-1. Compare the pair, then move the one pointer that can possibly improve the result.

🔑 Invariant — why it's safe Every pair that uses an index outside [L, R] has already been ruled out. So if an answer exists, it lies within [L, R]. When sum < target, a[L] with anything ≤ a[R] is also too small ⇒ a[L] is in no answer ⇒ L++ discards nothing. Symmetric for R--. The invariant survives every move.
// Two Sum II — sorted input, return 1-based indices
function twoSumSorted(a: number[], target: number): [number, number] {
  let L = 0, R = a.length - 1;
  while (L < R) {
    const sum = a[L] + a[R];
    if (sum === target) return [L + 1, R + 1];
    if (sum < target) L++;   // only L can raise the sum
    else R--;                // only R can lower it
  }
  return [-1, -1];
}
Same skeleton, different jobs Valid palindrome: compare a[L] vs a[R], both move inward. Container with most water: area = min(h[L],h[R])·(R−L); move the shorter wall — it's the bottleneck, and widening can't help the taller side.
// Container With Most Water — move the shorter wall
function maxArea(h: number[]): number {
  let L = 0, R = h.length - 1, best = 0;
  while (L < R) {
    best = Math.max(best, Math.min(h[L], h[R]) * (R - L));
    if (h[L] < h[R]) L++; else R--;
  }
  return best;
}

The generalization ladder: 2Sum → 3Sum → kSum

This is the deep structure — learn it once, never re-learn 3Sum/4Sum. 2Sum (sorted) is one converging sweep. 3Sum = fix index i, run 2Sum on the suffix. 4Sum = fix two. The general kSum peels one index via recursion down to the 2-pointer base case:

// kSum — sort `a` first, then call kSum(a, target, k, 0). 3Sum = kSum(a, 0, 3, 0).
function kSum(a: number[], target: number, k: number, start: number): number[][] {
  const res: number[][] = [];
  if (k === 2) {                                   // base case: converging 2-pointer
    let L = start, R = a.length - 1;
    while (L < R) {
      const s = a[L] + a[R];
      if (s === target) {
        res.push([a[L], a[R]]); L++; R--;
        while (L < R && a[L] === a[L - 1]) L++;     // skip duplicate lefts
        while (L < R && a[R] === a[R + 1]) R--;     // skip duplicate rights
      } else if (s < target) L++; else R--;
    }
    return res;
  }
  for (let i = start; i < a.length - k + 1; i++) { // peel one index
    if (i > start && a[i] === a[i - 1]) continue;   // skip duplicate picks
    for (const rest of kSum(a, target - a[i], k - 1, i + 1)) res.push([a[i], ...rest]);
  }
  return res;
}

Notice the recursion bottoms out in the converging sweep — two pointers is the engine; the loops just fix the extra indices.

🎤 Interview lens Probed: can you justify why moving a pointer never skips an answer (state the invariant), and "what if it's not sorted?" (sort vs. hash-map trade-off). · Escalation: 2Sum → 3Sum → kSum; "return all unique triples" (dedup); "closest sum" (track best, not exact).

4.2 · Fast & Slow — Floyd's tortoise & hare

“If there's a loop, the hare laps the tortoise.”

Setup: one pointer hops 1 step, the other 2. Used when you can't index a linked list and need a structural fact in O(1) space.

🔑 Invariant — why it's safe Per step, fast gains exactly 1 on slow. With no cycle, fast runs off the end (null) → terminates. With a cycle of length c, the gap is taken mod c and decreases to 0 in finite steps → guaranteed meeting. Both outcomes are bounded by O(n) steps.
function hasCycle(head: ListNode | null): boolean {
  let slow = head, fast = head;
  while (fast && fast.next) {
    slow = slow!.next;        // +1
    fast = fast.next.next;    // +2
    if (slow === fast) return true;   // hare laps tortoise
  }
  return false;               // hare reached null → no cycle
}

// Find the cycle's START: after they meet, reset one to head; advance both by 1.
function detectCycle(head: ListNode | null): ListNode | null {
  let slow = head, fast = head;
  while (fast && fast.next) {
    slow = slow!.next; fast = fast.next.next;
    if (slow === fast) {                 // meeting point
      let p = head;
      while (p !== slow) { p = p!.next; slow = slow!.next; }
      return p;                          // == entry of the loop
    }
  }
  return null;
}
Why the reset trick works Let the entry be μ steps from head and the meet be k steps into the loop. "Fast went twice as far" forces: distance head→entry ≡ distance meet→entry. So two walkers at speed 1 — one from head, one from the meet — collide exactly at the entry.

Same engine, other uses: middle node → return slow when fast hits the end; n-th from end → give fast an n-step head start, then move both until fast ends.

🎤 Interview lens Probed: prove it's O(1) space and argue why the two must meet; then derive the cycle-start reset on the spot. · Escalation: detect cycle → return its start → its length; then "Find the Duplicate Number" (treat the array as a linked list and reuse this verbatim).

4.3 · Read/Write — same direction, in place

“Write trails read; everything left of write is done.”

Setup: a slow "write" index marks where the next kept element goes; a fast "read" index scans everything.

🔑 Invariant — why it's safe After every step, a[0 .. write) is the finished, compacted answer and a[write .. read) is junk to be overwritten. Because write ≤ read always, you never clobber an element you haven't read yet.
// Move Zeroes — keep order, push all 0s to the end, O(1) space
function moveZeroes(a: number[]): void {
  let write = 0;
  for (let read = 0; read < a.length; read++) {
    if (a[read] !== 0) { [a[write], a[read]] = [a[read], a[write]]; write++; }
  }
}

// Remove Duplicates from Sorted Array — return new length
function removeDuplicates(a: number[]): number {
  if (a.length === 0) return 0;
  let write = 1;                          // a[0] always kept
  for (let read = 1; read < a.length; read++) {
    if (a[read] !== a[write - 1]) a[write++] = a[read];
  }
  return write;
}
Three-way variant: Dutch National Flag Sort 0/1/2 in one pass with three pointers. Invariant: [0,low) all 0s, [low,mid) all 1s, (high,end] all 2s, and [mid,high] is unexplored.
// Sort Colors (0,1,2) — one pass, O(1) space
function sortColors(a: number[]): void {
  let low = 0, mid = 0, high = a.length - 1;
  while (mid <= high) {
    if (a[mid] === 0)      { [a[low], a[mid]] = [a[mid], a[low]]; low++; mid++; }
    else if (a[mid] === 1) { mid++; }
    else                   { [a[mid], a[high]] = [a[high], a[mid]]; high--; } // DON'T mid++: re-check swapped-in value
  }
}
🎤 Interview lens Probed: truly in place, O(1) extra, and you never overwrite an unread slot (the write ≤ read invariant); is order preserved? · Escalation: remove dups → "allow at most 2 copies" → Dutch-flag 3-way partition in one pass.

4.4 · Two-sequence — one pointer per array

“Two queues, one output; take the smaller head.”

Setup: two sorted inputs, a pointer in each, advance whichever is "behind." This is the merge step of merge-sort and the backbone of intersection / subsequence checks.

🔑 Invariant — why it's safe out holds the correctly-sorted merge of the consumed prefixes a[0..i) and b[0..j). Taking the smaller of the two current heads keeps out sorted and never strands a smaller element.
// Merge two sorted arrays into a fresh result
function mergeSorted(a: number[], b: number[]): number[] {
  const out: number[] = [];
  let i = 0, j = 0;
  while (i < a.length && j < b.length) {
    if (a[i] <= b[j]) out.push(a[i++]);
    else out.push(b[j++]);
  }
  while (i < a.length) out.push(a[i++]);   // drain leftovers
  while (j < b.length) out.push(b[j++]);
  return out;
}

// Is Subsequence — does s appear in t in order?
function isSubsequence(s: string, t: string): boolean {
  let i = 0;
  for (let j = 0; i < s.length && j < t.length; j++) {
    if (s[i] === t[j]) i++;        // advance s only on a match
  }
  return i === s.length;
}
🎤 Interview lens Probed: what if one input is far larger or streamed? can you merge in place into a fixed buffer? · Escalation: merge two → "Merge Sorted Array" in place (fill from the back) → merge k lists (→ a heap; see the Heap sheet).

⏱️ 5 · Complexity

PatternTimeSpaceNote
Converging (already sorted)O(n)O(1)+O(n log n) if you must sort first
Converging — kSumO(n^(k−1))O(k) rec.k−1 fixed loops over an O(n) sweep; 3Sum = O(n²)

Two-sequence mergeO(n+m)O(n+m) / O(1)O(1) if you can merge into a given buffer
The amortized argument Every pointer only moves forward and never resets. Total work ≤ total distance the pointers can travel, which is linear in input size. That single observation is the proof for all four patterns — don't hand-wave it, state it.

⚠️ 6 · Pitfalls — and the test that catches each

BugThe input that exposes it
Loop bound <= instead of < — pairs an element with itself / double-counts.[3,3], target 6 → returns the same index twice.
Running converging on unsorted data.[4,1,3], target 4 → sweeps 4+3, 4+1, stops; misses the real pair (1,3).
3Sum/kSum emitting duplicate triples (missing skip-dup guards).[0,0,0,0], target 0 → emits [0,0,0] repeatedly.
Dutch flag: incrementing mid after a high-swap.[2,0,1] → the value swapped in from high is never re-checked → mis-sorted.
Fast/slow null deref (no fast && fast.next guard).[] or even-length [1,2] → crash on fast.next.next.
Returning the meeting point as the cycle start (skipping the reset).1→2→3→4→2 (cycle to node 2) → meet ≠ node 2.
Off-by-one: returning write − 1 as the length.all-distinct [1,2,3] → write ends at 3 (the count); subtracting gives 2.
🔗 This pattern, elsewhere Sliding window is a same-direction two-pointer (the read/write cousin) where "write" becomes a window-left that shrinks on a rule. Binary search is a converging pointer on the answer space, not the array — same "discard half, safely" logic. Floyd's fast/slow generalizes to any functional graph: "Find the Duplicate Number" treats the array as a linked list and reuses detectCycle verbatim. Merge (4.4) is the heart of merge sort and of merging k lists with a heap.
