🧠 1 · How to think — the return-value contract

A binary tree node is { val, left, right }. Almost every solution is one recursive function over subtrees. The skill that unlocks all of them is being ruthlessly clear about the contract of your recursion. Before writing a line, answer three questions:

The 3-question contract (1) RETURN: what single thing does dfs(node) hand back to its parent? (e.g. "the height of this subtree") (2) BASE CASE: what does dfs(null) return? (e.g. 0) (3) COMBINE: how does the parent fold its children's returns into its own answer — and does it also record something in a global along the way?

The single biggest tree confusion is mixing up what you return (one value, for the parent to keep recursing) with what you record (a global "best", which may use both children at once). Diameter is the perfect teacher.

Watch it get invented — Diameter of a Binary Tree

  1. Warm-up: height. height(node) RETURNS the node-count of the tallest path down. Base: height(null) = 0. Combine: 1 + max(height(left), height(right)).
  2. The twist. The diameter (longest path between any two nodes) bends at some node and uses both sides: leftHeight + rightHeight. But the parent can't use a "bent" length — it needs a straight height. So dfs must RETURN the height while RECORDING left + right into a global.
  3. Payoff. One O(n) pass; the global holds the answer even though the function returns something else.

🧩 4 · The five core patterns

Node shape: class TreeNode { val: number; left: TreeNode|null; right: TreeNode|null }. Each: a one-liner, a 🔑 invariant, a template, a 🎤 interview lens.

4.1 · Traversals (DFS & BFS)

“Pre = me-first, In = left-me-right (sorted for a BST), Post = children-first; BFS = a queue.”

🔑 Invariant — why it's safe DFS recursion processes an entire subtree before returning, so the call stack always mirrors the current root-to-node path. BFS's queue holds exactly one full level at a time, so draining it level by level visits nodes in non-decreasing depth.

Start with the simplest thing that works — recursion. All three depth-first orders are the same code; only where you place the visit relative to the two calls changes.

// Recursive DFS — the whole family is one line of reordering
function traverse(node: TreeNode | null, out: number[] = []): number[] {
  if (!node) return out;        // BASE: nothing below null
  // out.push(node.val);        //  ← visit HERE = PREORDER  (node, L, R)
  traverse(node.left, out);
  out.push(node.val);           //  ← visit HERE = INORDER   (L, node, R) — sorted in a BST
  traverse(node.right, out);
  // out.push(node.val);        //  ← visit HERE = POSTORDER (L, R, node) — the basis of §4.2
  return out;
}

Now the same orders without the implicit call stack — inorder via an explicit stack, and BFS via a queue:

// Iterative inorder (no recursion): push the left spine, pop, go right
function inorder(root: TreeNode | null): number[] {
  const out: number[] = [], st: TreeNode[] = []; let cur = root;
  while (cur || st.length) {
    while (cur) { st.push(cur); cur = cur.left; }   // dive left
    cur = st.pop()!; out.push(cur.val);             // visit
    cur = cur.right;                                // then right
  }
  return out;
}

// BFS level order — a queue, one level per outer iteration
function levelOrder(root: TreeNode | null): number[][] {
  if (!root) return [];
  const out: number[][] = [], q: TreeNode[] = [root];
  while (q.length) {
    const level: number[] = [], n = q.length;
    for (let i = 0; i < n; i++) {
      const x = q.shift()!; level.push(x.val);      // (use a head index for true O(n))
      if (x.left) q.push(x.left);
      if (x.right) q.push(x.right);
    }
    out.push(level);
  }
  return out;
}
🧵 Morris traversal — O(1) space Both the call stack and an explicit stack cost O(h). Morris walks inorder in O(1) extra space by temporarily threading each node's inorder predecessor (the rightmost node of its left subtree) back to the node: dive left, wire pred.right = cur as a breadcrumb; when you later return through that thread, unwire it and visit. It mutates pointers mid-walk, so reach for it only when space is explicitly required to be O(1) — but naming it signals depth.
🎤 Interview lens Probed: recursive vs iterative (explicit stack), BFS-vs-DFS choice, and "inorder of a BST is sorted." · Escalation: level order → zigzag → right-side view → vertical-order traversal.

4.2 · Return-value DFS (the heart)

“Compute children first, fold their returns into yours — and record a global if the answer bends.”

Setup: this is §1 made concrete. State the contract, then write three lines. Below, the escalation ladder: diameter (return-vs-record), balanced (height hijacked by a -1 failure sentinel), and the hardest, Max Path Sum.

🔑 Invariant — why it's safe Each call returns a correct summary of its entire subtree (guaranteed by the base case + the combine step), so a parent can trust its children's returns blindly. Recording into the global at every node means the answer is the best over all nodes, not just the root.
// Diameter — RETURN height, RECORD the bending path
function diameterOfBinaryTree(root: TreeNode | null): number {
  let best = 0;
  function height(node: TreeNode | null): number {   // CONTRACT: height of this subtree
    if (!node) return 0;                              // base case
    const L = height(node.left), R = height(node.right);
    best = Math.max(best, L + R);                     // RECORD: path bending at node
    return 1 + Math.max(L, R);                        // RETURN: straight height for parent
  }
  height(root);
  return best;
}

// Balanced? — RETURN height, but hijack it with -1 as a "subtree already failed" sentinel
function isBalanced(root: TreeNode | null): boolean {
  function height(node: TreeNode | null): number {   // CONTRACT: height, or -1 if unbalanced below
    if (!node) return 0;
    const L = height(node.left);  if (L === -1) return -1;   // short-circuit the failure upward
    const R = height(node.right); if (R === -1) return -1;
    if (Math.abs(L - R) > 1) return -1;                      // imbalance detected here → fail
    return 1 + Math.max(L, R);
  }
  return height(root) !== -1;
}

// Max Path Sum — clamp negative branches; RETURN a straight path, RECORD a bent one
function maxPathSum(root: TreeNode | null): number {
  let best = -Infinity;
  function gain(node: TreeNode | null): number {      // CONTRACT: best downward path sum from node
    if (!node) return 0;
    const L = Math.max(0, gain(node.left));           // ignore a negative branch
    const R = Math.max(0, gain(node.right));
    best = Math.max(best, node.val + L + R);          // RECORD: path that bends here
    return node.val + Math.max(L, R);                 // RETURN: straight path down
  }
  gain(root);
  return best;
}
🎤 Interview lens Probed: state the contract out loud (return vs record), the base case, and why you clamp child gains at 0. · Escalation: height → diameter → balanced (return -1 as a "failed" sentinel) → max path sum.

4.3 · BST = ordered

“Left < node < right — so search is binary, and inorder is sorted.”

Setup: a BST's ordering turns O(n) tree work into O(h). Two facts do everything: you can navigate by comparison, and an inorder walk emits values in sorted order.

🔑 Invariant — the range, not a local check A node is valid only if its value lies strictly inside the open range (lo, hi) handed down by its ancestors — left child tightens hi to the parent's value, right child tightens lo. A purely local "left < node < right" check passes invalid trees (a deep-left node can still violate a far ancestor).
// Validate BST — carry the allowed range down
function isValidBST(node: TreeNode | null, lo = -Infinity, hi = Infinity): boolean {
  if (!node) return true;
  if (node.val <= lo || node.val >= hi) return false;
  return isValidBST(node.left, lo, node.val) && isValidBST(node.right, node.val, hi);
}

// k-th smallest — inorder yields sorted order; stop at the k-th
function kthSmallest(root: TreeNode | null, k: number): number {
  const st: TreeNode[] = []; let cur = root;
  while (cur || st.length) {
    while (cur) { st.push(cur); cur = cur.left; }
    cur = st.pop()!;
    if (--k === 0) return cur.val;
    cur = cur.right;
  }
  return -1;
}
🎤 Interview lens Probed: the range invariant (not the local trap), inorder = sorted, and O(h) ops. · Escalation: validate → k-th smallest → LCA in a BST (walk by comparison, O(h)) → delete node.

4.4 · LCA & paths — postorder bubble-up

“If p and q surface from different children, you're standing on their ancestor.”

Setup: search both subtrees; a node where both sides report a hit is the lowest common ancestor. Everything bubbles up from the leaves (postorder).

🔑 Invariant — why it's safe lca(node) returns a target if it (or its subtree) contains one. A node gets a non-null from both children only when p and q are split across them — which makes it their lowest common ancestor. If both are on one side, that side's answer bubbles straight up.
// LCA in a general binary tree
function lowestCommonAncestor(root: TreeNode | null, p: TreeNode, q: TreeNode): TreeNode | null {
  if (!root || root === p || root === q) return root;   // found one (or hit bottom)
  const L = lowestCommonAncestor(root.left, p, q);
  const R = lowestCommonAncestor(root.right, p, q);
  if (L && R) return root;        // p and q on different sides → this is the LCA
  return L ?? R;                  // both on one side (or neither) → pass it up
}
🎤 Interview lens Probed: the L && R → root bubble-up, and the assumption that both nodes exist. · Escalation: LCA → path sum (root-to-leaf target) → all root-to-leaf paths (backtracking) → distance between two nodes (LCA + depth math).

4.5 · Construct & serialize

“Preorder hands you the root; inorder tells you where left ends and right begins.”

Setup: building a tree is recursion in reverse — identify the root, split the remaining nodes into left/right groups, recurse. Serialization is just a preorder walk with explicit null markers.

🔑 Invariant — why it's safe In preorder the first element of any segment is that subtree's root; locating it in inorder splits the rest into exactly the left and right subtrees (everything before it vs after). Each value is placed once, so the reconstruction is unique and O(n).
// Build a tree from preorder + inorder
function buildTree(preorder: number[], inorder: number[]): TreeNode | null {
  const pos = new Map(inorder.map((v, i) => [v, i]));
  let p = 0;
  function build(lo: number, hi: number): TreeNode | null {
    if (lo > hi) return null;
    const node = new TreeNode(preorder[p++]);   // preorder front = root
    const mid = pos.get(node.val)!;             // its index in inorder splits L | R
    node.left = build(lo, mid - 1);
    node.right = build(mid + 1, hi);
    return node;
  }
  return build(0, inorder.length - 1);
}

// Serialize / deserialize (preorder with '#' for null)
function serialize(root: TreeNode | null): string {
  const out: string[] = [];
  (function dfs(n: TreeNode | null) {
    if (!n) { out.push('#'); return; }
    out.push(String(n.val)); dfs(n.left); dfs(n.right);
  })(root);
  return out.join(',');
}
function deserialize(data: string): TreeNode | null {
  const vals = data.split(','); let i = 0;
  function build(): TreeNode | null {
    const v = vals[i++];
    if (v === '#') return null;
    const node = new TreeNode(+v);
    node.left = build(); node.right = build();
    return node;
  }
  return build();
}
🎤 Interview lens Probed: why preorder gives the root and inorder gives the split; null markers for serialization. · Escalation: pre+in → in+post → serialize/deserialize → "Flatten Binary Tree to a Linked List."
