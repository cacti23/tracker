🧠 1 · How to think — the return-value contract

A binary tree node is { val, left, right }. Almost every solution is one recursive function over subtrees. The skill that unlocks all of them is being ruthlessly clear about the contract of your recursion. Before writing a line, answer three questions:

🏢 The mental model — an org chart Picture the tree as a company. dfs(node) is a manager: they ask each direct report (child) for one summary number, fold those together, and report one number up to their own boss — without ever redoing a report's work. Trusting that summary blindly is the recursion leap of faith (your weak spot — lean on it). The three questions below are just that manager's job description.
The 3-question contract (1) RETURN: what single thing does dfs(node) hand back to its parent? (e.g. "the height of this subtree") (2) BASE CASE: what does dfs(null) return? (e.g. 0) (3) COMBINE: how does the parent fold its children's returns into its own answer — and does it also record something in a global along the way?

The single biggest tree confusion is mixing up what you return (one value, for the parent to keep recursing) with what you record (a global "best", which may use both children at once). Diameter is the perfect teacher.

Watch it get invented — Diameter of a Binary Tree

  1. Warm-up: height. height(node) RETURNS the node-count of the tallest path down. Base: height(null) = 0. Combine: 1 + max(height(left), height(right)).
  2. The twist. The diameter (longest path between any two nodes) bends at some node and uses both sides: leftHeight + rightHeight. But the parent can't use a "bent" length — it needs a straight height. So dfs must RETURN the height while RECORDING left + right into a global.
  3. Payoff. One O(n) pass; the global holds the answer even though the function returns something else.

🧩 4 · The five core patterns

Node shape: class TreeNode { val: number; left: TreeNode|null; right: TreeNode|null }. Each: a one-liner, a 🔑 invariant, a template, a 🎤 interview lens.

4.1 · Traversals (DFS & BFS)

“Pre = me-first, In = left-me-right (sorted for a BST), Post = children-first; BFS = a queue.”

🔑 Invariant — why it's safe The invariant: at any instant the DFS call stack holds exactly the path from the root down to the node you're on, and the BFS queue holds exactly one full level. Why that gives the order: a recursive call fully finishes a subtree before it returns, so where you place the visit — before, between, or after the two child calls — is the only thing that decides pre / in / post. And because the queue never mixes two levels, draining it front-to-back walks the tree strictly top-to-bottom, left-to-right.

Start with the simplest thing that works — recursion. All three depth-first orders are the same code; only where you place the visit relative to the two calls changes.

// Recursive DFS — the whole family is one line of reordering
function traverse(node: TreeNode | null, out: number[] = []): number[] {
  if (!node) return out;        // BASE: nothing below null
  // out.push(node.val);        //  ← visit HERE = PREORDER  (node, L, R)
  traverse(node.left, out);
  out.push(node.val);           //  ← visit HERE = INORDER   (L, node, R) — sorted in a BST
  traverse(node.right, out);
  // out.push(node.val);        //  ← visit HERE = POSTORDER (L, R, node) — the basis of §4.2
  return out;
}

Now the same orders without the implicit call stack — inorder via an explicit stack, and BFS via a queue:

// Iterative inorder (no recursion): push the left spine, pop, go right
function inorder(root: TreeNode | null): number[] {
  const out: number[] = [], st: TreeNode[] = []; let cur = root;
  while (cur || st.length) {
    while (cur) { st.push(cur); cur = cur.left; }   // dive left
    cur = st.pop()!; out.push(cur.val);             // visit
    cur = cur.right;                                // then right
  }
  return out;
}

// BFS level order — a queue, one level per outer iteration
function levelOrder(root: TreeNode | null): number[][] {
  if (!root) return [];
  const out: number[][] = [], q: TreeNode[] = [root];
  while (q.length) {
    const level: number[] = [], n = q.length;
    for (let i = 0; i < n; i++) {
      const x = q.shift()!; level.push(x.val);      // (use a head index for true O(n))
      if (x.left) q.push(x.left);
      if (x.right) q.push(x.right);
    }
    out.push(level);
  }
  return out;
}
🧵 Morris traversal — O(1) space · advanced, skip on first pass Both the call stack and an explicit stack cost O(h) memory. Morris does inorder in O(1) extra space with one trick: before descending into a left subtree, it ties a string back to itself — it points the rightmost node of that left subtree (the node you'll visit just before this one, your inorder predecessor) back at the current node. Later, when the left subtree is done, that string is how you climb back up without a stack; you untie it and visit. The only thing to remember: "thread each node to its inorder predecessor so you can return without a stack." That one sentence is all an interview wants — the full code is famously finicky and almost never required.
🎤 Interview lens What they're really testing: can you write a traversal both recursively and iteratively (with an explicit stack), pick BFS vs DFS for the task, and recall that an inorder walk of a BST comes out sorted. Nail it and they escalate: level order → zigzag → right-side view → vertical-order traversal.

4.2 · Return-value DFS (the heart)

“Compute children first, fold their returns into yours — and record a global if the answer bends.”

Setup: this is the org-chart manager made concrete. State the contract, then the body is literally three lines: (1) BASE — what does an empty subtree (null) report? (2) COMBINE — ask both children, fold their returns L and R into your answer. (3) RETURN / RECORD — hand one summary up, and if the answer can bend here, also write it to a global. Below, the same dfs three ways, each one twist harder: diameter (return-vs-record), balanced (height hijacked by a -1 "failed" sentinel), and the hardest, Max Path Sum.

🔑 Invariant — why it's safe The invariant (say it before you code): every time dfs(node) returns, two things are already true — (1) it handed its parent a correct summary of its whole subtree, and (2) it has compared the best answer bending at this node against the global. Why that's enough: (1) lets a parent trust a child's number without re-checking it — the org-chart manager trusts each report. (2) means once the root returns, every possible bending point has been weighed, so the global is the true answer even though the function never returns it.
// Diameter — RETURN height, RECORD the bending path
function diameterOfBinaryTree(root: TreeNode | null): number {
  let best = 0;
  function height(node: TreeNode | null): number {   // CONTRACT: height of this subtree
    if (!node) return 0;                              // base case
    const L = height(node.left), R = height(node.right);
    best = Math.max(best, L + R);                     // RECORD: path bending at node
    return 1 + Math.max(L, R);                        // RETURN: straight height for parent
  }
  height(root);
  return best;
}

// Balanced? — RETURN height, but hijack it with -1 as a "subtree already failed" sentinel
function isBalanced(root: TreeNode | null): boolean {
  function height(node: TreeNode | null): number {   // CONTRACT: height, or -1 if unbalanced below
    if (!node) return 0;
    const L = height(node.left);  if (L === -1) return -1;   // short-circuit the failure upward
    const R = height(node.right); if (R === -1) return -1;
    if (Math.abs(L - R) > 1) return -1;                      // imbalance detected here → fail
    return 1 + Math.max(L, R);
  }
  return height(root) !== -1;
}

// Max Path Sum — clamp negative branches; RETURN a straight path, RECORD a bent one
function maxPathSum(root: TreeNode | null): number {
  let best = -Infinity;
  function gain(node: TreeNode | null): number {      // CONTRACT: best downward path sum from node
    if (!node) return 0;
    const L = Math.max(0, gain(node.left));           // ignore a negative branch
    const R = Math.max(0, gain(node.right));
    best = Math.max(best, node.val + L + R);          // RECORD: path that bends here
    return node.val + Math.max(L, R);                 // RETURN: straight path down
  }
  gain(root);
  return best;
}
🎤 Interview lens What they're really testing: can you separate what you return from what you record, name your base case, and justify clamping a negative child at 0 (a branch that only hurts you, you simply don't take). Nail it and they escalate: height → diameter → balanced (-1 sentinel) → max path sum — each is the same dfs with one new twist.

4.3 · BST = ordered

“Left < node < right — so search is binary, and inorder is sorted.”

Setup: a plain tree can force you to check every node — O(n). A BST is binary search frozen into a data structure: because left < node < right, one comparison tells you which half to keep and which to throw away — exactly like guessing a number in 1–100 with "higher / lower" hints. So you walk a single root-to-leaf path instead of the whole tree: O(h), and h ≈ log n when balanced. Two facts do everything: you navigate by comparison (that's the binary search), and an inorder walk emits values in sorted order.

🔑 Invariant — the range, not a local check The invariant: a node is valid only if its value lies strictly inside the open range (lo, hi) handed down by its ancestors — left child tightens hi to the parent's value, right child tightens lo. A purely local "left < node < right" check passes invalid trees (a deep-left node can still violate a far ancestor).
// Validate BST — carry the allowed range down
function isValidBST(node: TreeNode | null, lo = -Infinity, hi = Infinity): boolean {
  if (!node) return true;
  if (node.val <= lo || node.val >= hi) return false;
  return isValidBST(node.left, lo, node.val) && isValidBST(node.right, node.val, hi);
}

// k-th smallest — inorder yields sorted order; stop at the k-th
function kthSmallest(root: TreeNode | null, k: number): number {
  const st: TreeNode[] = []; let cur = root;
  while (cur || st.length) {
    while (cur) { st.push(cur); cur = cur.left; }
    cur = st.pop()!;
    if (--k === 0) return cur.val;
    cur = cur.right;
  }
  return -1;
}
🎤 Interview lens What they're really testing: do you bound each node by the range its ancestors allow (not the local "left < node < right" trap), do you know inorder comes out sorted, and can you state why ops are O(h). Nail it and they escalate: validate → k-th smallest → LCA in a BST (walk by comparison, O(h)) → delete a node.

4.4 · LCA & paths — postorder bubble-up

“If p and q surface from different children, you're standing on their ancestor.”

Setup: "LCA" is literally lowest common ancestor — picture two people tracing their family trees upward; the first ancestor they share is the answer. The code finds that merge point by asking each subtree "is p or q below you?": the node that hears "yes" from both sides is where their two paths first meet. Everything bubbles up from the leaves (postorder).

🔑 Invariant — why it's safe The invariant: lca(node) returns a target node if its subtree contains one, else null. A node gets a non-null from both children only when p and q are split across them — which makes it their lowest common ancestor. If both are on one side, that side's answer bubbles straight up.
// LCA in a general binary tree
function lowestCommonAncestor(root: TreeNode | null, p: TreeNode, q: TreeNode): TreeNode | null {
  if (!root || root === p || root === q) return root;   // found one (or hit bottom)
  const L = lowestCommonAncestor(root.left, p, q);
  const R = lowestCommonAncestor(root.right, p, q);
  if (L && R) return root;        // p and q on different sides → this is the LCA
  return L ?? R;                  // both on one side (or neither) → pass it up
}
🎤 Interview lens What they're really testing: can you explain the L && R → root bubble-up (a hit from both sides ⇒ you're the merge point), and do you notice the hidden assumption that both nodes actually exist in the tree. Nail it and they escalate: LCA → path sum (root-to-leaf target) → all root-to-leaf paths (backtracking) → distance between two nodes (LCA + depth math).

4.5 · Construct & serialize

“Preorder hands you the root; inorder tells you where left ends and right begins.”

Setup: building a tree is recursion in reverse — identify the root, split the remaining nodes into left/right groups, recurse. Serialization is just a preorder walk with explicit null markers.

🔑 Invariant — why it's safe The invariant: in preorder the first element of any segment is that subtree's root; locating it in inorder splits the rest into exactly the left and right subtrees (everything before it vs after). Each value is placed once, so the reconstruction is unique and O(n).
// Build a tree from preorder + inorder
function buildTree(preorder: number[], inorder: number[]): TreeNode | null {
  const pos = new Map(inorder.map((v, i) => [v, i]));
  let p = 0;
  function build(lo: number, hi: number): TreeNode | null {
    if (lo > hi) return null;
    const node = new TreeNode(preorder[p++]);   // preorder front = root
    const mid = pos.get(node.val)!;             // its index in inorder splits L | R
    node.left = build(lo, mid - 1);
    node.right = build(mid + 1, hi);
    return node;
  }
  return build(0, inorder.length - 1);
}

// Serialize / deserialize (preorder with '#' for null)
function serialize(root: TreeNode | null): string {
  const out: string[] = [];
  (function dfs(n: TreeNode | null) {
    if (!n) { out.push('#'); return; }
    out.push(String(n.val)); dfs(n.left); dfs(n.right);
  })(root);
  return out.join(',');
}
function deserialize(data: string): TreeNode | null {
  const vals = data.split(','); let i = 0;
  function build(): TreeNode | null {
    const v = vals[i++];
    if (v === '#') return null;
    const node = new TreeNode(+v);
    node.left = build(); node.right = build();
    return node;
  }
  return build();
}
🎤 Interview lens What they're really testing: can you explain why preorder's front is always the root and inorder's split gives left vs right, and why serialization needs explicit null markers (without them the string is ambiguous). Nail it and they escalate: pre+in → in+post → serialize/deserialize → "Flatten Binary Tree to a Linked List."
