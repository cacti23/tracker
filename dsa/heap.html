🏔️ Heap / Priority Queue

A learning sheet — when you repeatedly need the smallest or largest thing (but not everything sorted), a heap gives it to you in O(log n).

🧠 1 · How to think (and invent it)

A heap is a complete binary tree kept in a flat array, obeying one rule — the heap property: every parent is ≤ its children (min-heap) or ≥ (max-heap). That's it. It does not keep things fully sorted; it keeps just enough order that the extreme is always at the root. Peek is O(1); insert and extract are O(log n) (one walk up or down the tree height).

Because the array is implicit, the tree links are pure arithmetic: for index i, parent = (i−1)/2, children = 2i+1 and 2i+2. Two operations maintain the property: sift-up (after a push, bubble the newcomer up) and sift-down (after replacing the root, sink it down).

Watch it get invented — the k largest of a stream

  1. Start brute. Sort all n → O(n log n), and impossible if the data streams in and doesn't fit in memory.
  2. Spot the structure. You only ever need the k best so far. A newcomer matters only if it beats the smallest of those k — so you need fast access to that smallest.
  3. The leap (and the twist). Keep a min-heap of size k. Push each number; if the heap exceeds k, pop the minimum. Counter-intuitively, you use a min-heap to track the largest k — its root is the weakest survivor, i.e. the k-th largest.
  4. Payoff. O(n log k) time, O(k) space, works on an infinite stream.

4.1 · Mechanics — sift-up & sift-down

“Push and bubble up; pop the root, move the last up, and sink it down.”

🔑 Invariant — why it's safe The heap property (parent ≤ both children) holds everywhere except at the one node being fixed. Sift-up/down swaps that node toward its correct level along a single root-to-leaf path — height log n — restoring the property globally.
class MinHeap<T> {
  private h: T[] = [];
  constructor(private less: (a: T, b: T) => boolean) {}   // less(a,b)=a<b → min-heap
  size() { return this.h.length; }
  peek(): T { return this.h[0]; }
  push(x: T) { this.h.push(x); this.up(this.h.length - 1); }
  pop(): T {
    const top = this.h[0], last = this.h.pop()!;
    if (this.h.length) { this.h[0] = last; this.down(0); }
    return top;
  }
  private up(i: number) {
    while (i > 0) { const p = (i - 1) >> 1; if (!this.less(this.h[i], this.h[p])) break;
      [this.h[i], this.h[p]] = [this.h[p], this.h[i]]; i = p; }
  }
  private down(i: number) {
    const n = this.h.length;
    while (true) {
      let s = i; const l = 2 * i + 1, r = 2 * i + 2;
      if (l < n && this.less(this.h[l], this.h[s])) s = l;
      if (r < n && this.less(this.h[r], this.h[s])) s = r;
      if (s === i) break;
      [this.h[i], this.h[s]] = [this.h[s], this.h[i]]; i = s;
    }
  }
}
// a MAX-heap is just a MinHeap with the comparison flipped:
const maxHeap = () => new MinHeap<number>((a, b) => a > b);
🎤 Interview lens Probed: the index arithmetic, sift-up vs sift-down, and that build-heap is O(n), not O(n log n) (sift-down from the bottom up). · Escalation: build-heap → heapsort → a k-ary heap / decrease-key for Dijkstra.

4.2 · Top-K / k-th

“For the k largest, keep a MIN-heap of size k — its root is the k-th largest.”

Setup: the heap of size k always holds the best k seen, and its root is the weakest of them — exactly the threshold a newcomer must beat.

🔑 Invariant — why it's safe After each step the heap contains the k largest elements seen so far, and its root is their minimum. Any newcomer smaller than the root cannot be among the top k, so popping the root when the size exceeds k never discards a true top-k element.
// k-th largest in an array (or stream)
function kthLargest(nums: number[], k: number): number {
  const heap = new MinHeap<number>((a, b) => a < b);   // MIN-heap (note!)
  for (const x of nums) {
    heap.push(x);
    if (heap.size() > k) heap.pop();    // drop the smallest → keep the largest k
  }
  return heap.peek();                    // root = k-th largest; heap = the top k
}
🎤 Interview lens Probed: why a min-heap finds the max-k, the size cap, and heap O(n log k) vs quickselect O(n). · Escalation: k-th largest → "Top K Frequent" (heap, or bucket sort) → "K Closest Points to Origin."

4.3 · K-way merge

“Heap the k current heads; pop the smallest, push its successor.”

Setup: to merge k sorted sequences, the global next-smallest is always the min of the k front elements — exactly what a min-heap of size k serves.

🔑 Invariant — why it's safe The heap always contains exactly one (the current front) element from each not-yet-exhausted sequence. So its root is the smallest unemitted element overall; popping it and pushing that sequence's next keeps the invariant.
// Merge k sorted linked lists
function mergeKLists(lists: (ListNode | null)[]): ListNode | null {
  const heap = new MinHeap<ListNode>((a, b) => a.val < b.val);
  for (const l of lists) if (l) heap.push(l);
  const dummy = new ListNode(0); let tail = dummy;
  while (heap.size()) {
    const node = heap.pop();
    tail.next = node; tail = node;
    if (node.next) heap.push(node.next);   // pull the next from that list
  }
  return dummy.next;
}
🎤 Interview lens Probed: heap size stays k, so it's O(n log k) not O(n log n). · Escalation: merge k lists → "Smallest Range Covering Elements from K Lists" → "K-th Smallest in a Sorted Matrix."

4.4 · Two heaps — running median & balance

“Max-heap holds the lower half, min-heap the upper; the median sits between.”

Setup: split the data into a lower half (a max-heap, so its top is the lower-half max) and an upper half (a min-heap, top = upper-half min). Keep the sizes balanced and the median is at the tops.

🔑 Invariant — why it's safe Two facts held after every insert: (1) every element in lo ≤ every element in hi; (2) lo.size equals hi.size or is one larger. Then the median is lo.top (odd count) or the average of the two tops (even).
class MedianFinder {
  private lo = new MinHeap<number>((a, b) => a > b);  // MAX-heap (lower half)
  private hi = new MinHeap<number>((a, b) => a < b);  // MIN-heap (upper half)
  addNum(x: number) {
    this.lo.push(x);
    this.hi.push(this.lo.pop());                     // pass lo's max into hi (keeps lo ≤ hi)
    if (this.hi.size() > this.lo.size()) this.lo.push(this.hi.pop()); // rebalance: lo ≥ hi
  }
  findMedian(): number {
    return this.lo.size() > this.hi.size()
      ? this.lo.peek()
      : (this.lo.peek() + this.hi.peek()) / 2;
  }
}
🎤 Interview lens Probed: the two invariants and the funnel-then-rebalance trick (why push to lo, move to hi, maybe move back). · Escalation: stream median → "Sliding Window Median" (lazy deletion of leaving elements) → "IPO" (two heaps keyed by capital and profit).

4.5 · Greedy driven by a heap

“Repeatedly pull the best available option; push back what it spawns.”

Setup: many scheduling/simulation problems reduce to "always act on the current most-urgent / cheapest / earliest-ending item" — a heap serves that item in O(log n).

🔑 Why the greedy choice is safe The heap's top is the globally best available option right now (here, the earliest-freeing room). Taking it never forecloses a better future — anything you skip is still on the heap next round. For Meeting Rooms: if even the soonest-ending room isn't free by this meeting's start, none are, so a new room is genuinely required.
// Meeting Rooms II — fewest rooms needed
function minMeetingRooms(intervals: number[][]): number {
  intervals.sort((a, b) => a[0] - b[0]);                 // by start
  const ends = new MinHeap<number>((a, b) => a < b);     // min-heap of end times
  let rooms = 0;
  for (const [start, end] of intervals) {
    if (ends.size() && ends.peek() <= start) ends.pop();  // a room freed up
    ends.push(end);
    rooms = Math.max(rooms, ends.size());                // peak concurrency
  }
  return rooms;
}
🎤 Interview lens Probed: justify the greedy choice, and use lazy deletion when "remove a specific item" is needed (skip stale tops on pop). · Escalation: meeting rooms → "Task Scheduler" / "Reorganize String" → "Minimum Cost to Connect Sticks" (Huffman) → Dijkstra / Prim (a heap of frontier edges).

The size-k insight Capping the heap at k turns "process n items" into O(n log k) — a big win when k ≪ n, and the reason top-k/k-way-merge use a heap rather than sorting everything.

➕ Heap + greedy escalations — Meeting Rooms III (2402) · Rearrange String k Apart (358) · Max Events (1353) · Hire K Workers (857)
Four ways a heap drives a greedy: two heaps for rooms, a cooldown queue, earliest-deadline-first, and sort by one key, heap on another.
// 2402 Meeting Rooms III — free rooms (by index) + busy rooms (by end time, then index)
function mostBooked(n: number, meetings: number[][]): number {
  meetings.sort((a, b) => a[0] - b[0]);
  const free = new MinHeap<number>((a, b) => a < b);
  for (let r = 0; r < n; r++) free.push(r);
  const busy = new MinHeap<[number, number]>((a, b) => a[0] < b[0] || (a[0] === b[0] && a[1] < b[1]));   // [end, room]
  const used: number[] = new Array(n).fill(0);
  for (const [s, e] of meetings) {
    while (busy.size() && busy.peek()[0] <= s) free.push(busy.pop()[1]);   // release rooms that finished
    let room: number, end: number;
    if (free.size()) { room = free.pop(); end = e; }
    else { const [t, r] = busy.pop(); room = r; end = t + (e - s); }       // delayed: keeps its DURATION
    busy.push([end, room]); used[room]++;
  }
  let best = 0;
  for (let r = 1; r < n; r++) if (used[r] > used[best]) best = r;          // ties → lowest index
  return best;
}

// 358 Rearrange String k Distance Apart — max-heap by count + cooldown queue
function rearrangeString(s: string, k: number): string {
  if (k <= 1) return s;
  const cnt = new Map<string, number>();
  for (const ch of s) cnt.set(ch, (cnt.get(ch) ?? 0) + 1);
  const heap = new MinHeap<[number, string]>((a, b) => a[0] > b[0] || (a[0] === b[0] && a[1] < b[1]));   // most frequent first
  for (const [ch, c] of cnt) heap.push([c, ch]);
  const wait: [number, string][] = []; let res = '';
  while (heap.size()) {
    const [c, ch] = heap.pop(); res += ch;
    wait.push([c - 1, ch]);
    if (wait.length >= k) { const [c2, ch2] = wait.shift()!; if (c2 > 0) heap.push([c2, ch2]); }   // usable again after k placements
  }
  return res.length === s.length ? res : '';
}

// 1353 Maximum Number of Events That Can Be Attended — earliest deadline first
function maxEvents(events: number[][]): number {
  events.sort((a, b) => a[0] - b[0]);
  const heap = new MinHeap<number>((a, b) => a < b);                       // end days
  let i = 0, day = 0, count = 0;
  while (i < events.length || heap.size()) {
    if (!heap.size()) day = Math.max(day, events[i][0]);                   // jump over empty days
    while (i < events.length && events[i][0] <= day) heap.push(events[i++][1]);
    while (heap.size() && heap.peek() < day) heap.pop();                   // expired
    if (heap.size()) { heap.pop(); count++; }                              // attend the one ending soonest
    day++;
  }
  return count;
}

// 857 Minimum Cost to Hire K Workers — sort by wage/quality, heap keeps the K smallest qualities
function mincostToHireWorkers(quality: number[], wage: number[], k: number): number {
  const workers = quality.map((q, i) => ({ q, r: wage[i] / q })).sort((a, b) => a.r - b.r);
  const heap = new MinHeap<number>((a, b) => a > b);                       // max-heap of qualities
  let sumQ = 0, best = Infinity;
  for (const w of workers) {
    heap.push(w.q); sumQ += w.q;
    if (heap.size() > k) sumQ -= heap.pop();                               // drop the LARGEST quality
    if (heap.size() === k) best = Math.min(best, w.r * sumQ);              // w.r is the group rate (max ratio so far)
  }
  return best;
}
⚠️ Traps 2402: a delayed meeting keeps its duration; break end-time ties by room index. 358: release a character only after k placements. 1353: drop expired events before attending; jump day when the heap is empty. 857: compute the cost only when the heap holds exactly k; the current ratio is valid only because you sorted ascending.
