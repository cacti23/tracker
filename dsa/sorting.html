🧠 1 · How to think (and invent it)

Sorting wears two hats. Hat 1 — the toolbox: the library sorts in O(n log n), so you usually just call it — but you must know which sort it uses and its guarantees (stable? in-place? worst case?), because those decide correctness. Hat 2 — the weapon: a huge class of problems isn't "sort," but becomes trivial once sorted — enabling two pointers, greedy, sweep lines, or a custom comparator.

Underneath the named algorithms sit three reusable subroutines that show up as building blocks far beyond sorting: the merge (combine two sorted runs), the partition (split around a pivot), and quickselect (find the k-th element without fully sorting).

Watch it get invented — Merge Sort (divide & conquer)

  1. Start brute. Insertion/selection sort is O(n²) — every element compared against many others.
  2. The leap. Split the array in half, sort each half (recursively), then notice: two already-sorted halves can be stitched into one sorted whole in a single linear pass — the merge step (a two-sequence two-pointer).
  3. The recurrence. T(n) = 2·T(n/2) + O(n) → O(n log n). Log levels of halving, each level doing O(n) of merging.
  4. Payoff. Guaranteed O(n log n), and stable (keep <= in the merge) — the cost is O(n) extra space.
Mental checklist Before reaching for any sort, ask: (1) do I need the whole thing sorted, or just the top-k / k-th? (2) is the data a bounded integer range (→ linear sort)? (3) do I need stability? (4) is the real problem actually "sort first, then sweep/two-pointer"?

🧩 4 · The five core patterns

§4.1–4.3 are the divide-and-conquer trio (merge, partition, select). §4.4–4.5 are the "beat or avoid the sort" moves. Each: a one-liner, a 🔑 invariant, a template, a 🎤 interview lens.

4.1 · Merge sort

“Sort each half, then zip the two sorted runs together.”

🔑 Invariant — why it's safe Each recursive call returns a fully-sorted sub-array. The merge always emits the smaller of the two current heads, so its output is sorted and contains every element — and using <= on ties preserves left-before-right order (stability).
function mergeSort(a: number[]): number[] {
  if (a.length <= 1) return a;
  const mid = a.length >> 1;
  return merge(mergeSort(a.slice(0, mid)), mergeSort(a.slice(mid)));
}
// the merge step IS a two-sequence two-pointer
function merge(a: number[], b: number[]): number[] {
  const out: number[] = []; let i = 0, j = 0;
  while (i < a.length && j < b.length) out.push(a[i] <= b[j] ? a[i++] : b[j++]); // <= → stable
  while (i < a.length) out.push(a[i++]);
  while (j < b.length) out.push(b[j++]);
  return out;
}
🎤 Interview lens Probed: stability, the O(n) space, and the O(n log n) recurrence. · Escalation: sort → "Count Inversions" (count cross-pairs during merge) → "Merge k Sorted Lists" → external merge sort for data that doesn't fit in memory.

4.2 · Quicksort & partition

“Pick a pivot, shove smaller-left / bigger-right, recurse on each side.”

Setup: the partition is the reusable jewel — it places the pivot at its final sorted index and returns it. Quicksort just recurses on both sides; quickselect (§4.3) recurses on one.

🔑 Invariant — why it's safe During the sweep, a[lo..i) are all < pivot and a[i..j) are all ≥ pivot. Swapping the pivot into slot i at the end puts it exactly where it belongs, so each side can be sorted independently.
function quickSort(a: number[], lo = 0, hi = a.length - 1): void {
  if (lo >= hi) return;
  const p = partition(a, lo, hi);
  quickSort(a, lo, p - 1);
  quickSort(a, p + 1, hi);
}
// Lomuto partition; randomize the pivot to dodge the O(n²) worst case
function partition(a: number[], lo: number, hi: number): number {
  const r = lo + Math.floor(Math.random() * (hi - lo + 1));
  [a[r], a[hi]] = [a[hi], a[r]];          // random pivot → swap to the end
  const pivot = a[hi]; let i = lo;
  for (let j = lo; j < hi; j++) if (a[j] < pivot) { [a[i], a[j]] = [a[j], a[i]]; i++; }
  [a[i], a[hi]] = [a[hi], a[i]];
  return i;
}
🎤 Interview lens Probed: the O(n²) worst case (sorted input + last-element pivot) and the random-pivot fix; that it's in-place but not stable. · Escalation: partition → quickselect (§4.3) → 3-way partition (Dutch flag) when there are many duplicate keys.

4.3 · Quickselect — the k-th without sorting

“Partition, then recurse into only the side that holds k.”

Setup: a full sort is wasteful if you only need rank k. After a partition, the pivot's final index tells you which side k is on — keep only that side.

🔑 Invariant — why it's O(n) average Each partition discards (on average) half the remaining elements, so work is n + n/2 + n/4 + … = O(n) (a geometric series, unlike sort's O(n log n)). Because you recurse into one side, the log factor disappears.
// k-th SMALLEST (0-indexed k); for k-th largest use a.length-1-k
function quickselect(a: number[], k: number): number {
  let lo = 0, hi = a.length - 1;
  while (true) {
    const p = partition(a, lo, hi);   // same partition as §4.2
    if (p === k) return a[p];
    if (p < k) lo = p + 1;            // k is to the right
    else hi = p - 1;                  // k is to the left
  }
}
🎤 Interview lens Probed: the average O(n) geometric-series argument and the O(n²) worst case (random pivot or median-of-medians for a guaranteed bound). · Escalation: k-th largest → "Top K Frequent Elements" (or bucket sort) → "K Closest Points to Origin."

4.4 · Non-comparison (linear) sorts

“Bounded integer keys? Count them — no comparisons, O(n).”

Setup: comparison sorts are stuck at Ω(n log n). If keys are integers in a small range, you can tally instead of compare and beat that bound.

🔑 Invariant — why it's safe count[v] is the exact number of times v appears. Emitting values 0, 1, 2, … in order, each repeated its count, produces a sorted array — correctness comes from the range being known and small, not from comparisons.
// Counting sort — keys in [0, maxVal]; O(n + maxVal)
function countingSort(a: number[], maxVal: number): number[] {
  const count = new Array(maxVal + 1).fill(0);
  for (const x of a) count[x]++;
  const out: number[] = [];
  for (let v = 0; v <= maxVal; v++) while (count[v]-- > 0) out.push(v);
  return out;
}
🎤 Interview lens Probed: when O(n) actually beats O(n log n) (range ≪ n log n), and counting sort's stability if you emit by prefix-sum position. · Escalation: counting → "Sort Colors" (3-way Dutch flag, one pass) → bucket sort for "Top K Frequent" → radix sort ("Maximum Gap").

4.5 · Sort-as-preprocessing (the meta-move)

“The problem isn't sorting — but sorting makes it fall over.”

Setup: sorting imposes order, which unlocks linear follow-ups: two pointers, greedy-by-order, sweep lines, grouping, or a custom comparator that defines the order you actually need.

// Largest Number — order so that concatenation is biggest (custom total order)
function largestNumber(nums: number[]): string {
  const s = nums.map(String).sort((x, y) => (y + x).localeCompare(x + y)); // "x then y" vs "y then x"
  return s[0] === '0' ? '0' : s.join('');   // all zeros → "0"
}
The "sort unlocks…" menu two pointers: 3Sum, pair-sum on sorted (two-pointers). greedy by order: assign meetings, schedule, activity selection. sweep line: merge intervals, meeting rooms (sort by start; see the Intervals sheet). grouping: group anagrams (sorted string as the key). custom comparator: reconstruct queue, largest number.
🎤 Interview lens Probed: define the comparator's total order and argue it's transitive (a non-transitive comparator silently corrupts the sort). · Escalation: largest number → "Merge Intervals" / "Meeting Rooms II" (sort + sweep) → "Reconstruct the Queue" → "Group Anagrams."

➕ Sorting-adjacent tricks — First Missing Positive (41) · Car Fleet (853) · Longest Consecutive (128) · Disappeared Numbers (448)
When the values are bounded by n the array can be its own hash table (41, 448) — cyclic sort or sign-marking, O(n) with no sort. 128 is "don't sort, use a set and start only at sequence heads". 853 is sort-then-one-pass.
// 41 First Missing Positive — cyclic sort: put v at index v-1
function firstMissingPositive(nums: number[]): number {
  const n = nums.length;
  for (let i = 0; i < n; i++) {
    while (nums[i] >= 1 && nums[i] <= n && nums[nums[i] - 1] !== nums[i]) {
      const j = nums[i] - 1, tmp = nums[i];          // temp swap — [nums[i], nums[nums[i]-1]] = ... reads the modified nums[i]
      nums[i] = nums[j]; nums[j] = tmp;
    }
  }
  for (let i = 0; i < n; i++) if (nums[i] !== i + 1) return i + 1;
  return n + 1;
}

// 853 Car Fleet — sort by position (closest to target first), compare arrival times
function carFleet(target: number, position: number[], speed: number[]): number {
  const cars = position.map((p, i) => [p, (target - p) / speed[i]]).sort((a, b) => b[0] - a[0]);
  let fleets = 0, lead = 0;
  for (const [, t] of cars) if (t > lead) { fleets++; lead = t; }   // slower than the fleet ahead → new fleet
  return fleets;
}

// 128 Longest Consecutive Sequence — O(n): only count from sequence HEADS
function longestConsecutive(nums: number[]): number {
  const set = new Set(nums); let best = 0;
  for (const x of set) {
    if (set.has(x - 1)) continue;                    // not a head
    let len = 1; while (set.has(x + len)) len++;
    best = Math.max(best, len);
  }
  return best;
}

// 448 Find All Numbers Disappeared — mark presence by negating nums[v-1]
function findDisappearedNumbers(nums: number[]): number[] {
  for (const x of nums) { const i = Math.abs(x) - 1; if (nums[i] > 0) nums[i] = -nums[i]; }
  const res: number[] = [];
  nums.forEach((v, i) => { if (v > 0) res.push(i + 1); });
  return res;
}
⚠️ Traps 41: compare the target slot's value in the while condition (comparing to i loops forever on duplicates). 853: merge on t ≤ lead. 128: skip non-heads or it is O(n²). 448: read with Math.abs, negate only if still positive.
