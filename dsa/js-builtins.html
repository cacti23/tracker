1 · 🗂️ Map & Set — Basics, and .keys()/.values()/.entries() Are ITERATORS

const m = new Map<string, number>();
m.set('a', 1); m.get('a'); m.has('a'); m.delete('a');
const s = new Set<number>();
s.add(5); s.has(5); s.delete(5);
m.size; s.size;          // PROPERTY, no ()
for (const [k, v] of m) {}
for (const v of s) {}

new Set([1, 2, 3]);      // ✅ needs an ARRAY
new Set(1, 2, 3);        // ❌ TypeError

m.keys().sort((a, b) => a - b);            // ❌ iterator has no .sort()
[...m.keys()].sort((a, b) => a - b);       // ✅ spread to array first
Array.from(m.values());                    // ✅ same idea
🚨 On a Map or Set, .keys(), .values() and .entries() return an iterator, not an array — so no .sort(), .map(), .filter() until you convert with [...x] or Array.from(x). A bare Set is the same: iterable, not an array. (Set: .keys() is .values(), and .entries() gives [v, v].)
🔑 Don't forget the comparator .sort() with no comparator sorts as STRINGS — 10 before 2. Always pass (a, b) => a - b for numbers.

Spreading an iterator with [...] can need "target": "ES2015"+ (or downlevelIteration) in tsconfig — not an issue on LeetCode.

📌 .size = property, no parens. .keys()/.values()/.entries() = iterator → convert first, THEN use array methods.

2 · ⚠️ Common Mix-ups

  • .size (Map/Set) and .length (array/string) → properties, no ()
  • .entries() exists on Array, Map and Set → method, needs (), returns an iterator on all three (Array: [index, value], Map: [key, value], Set: [v, v])
  • Object.entries(obj) → a function that returns a real array; m.entries() → a method that returns an iterator

3 · 🏗️ MinPriorityQueue / MaxPriorityQueue (LeetCode's built-in library)

const pq = new MinPriorityQueue<number>();                    // simple numeric
const pq = new MinPriorityQueue<number[]>(x => x[0]);          // callback extracts comparison key
const pq = new MaxPriorityQueue<number[]>(x => x[0]);           // reverse order, same API

pq.enqueue(item);   // O(log n)
pq.dequeue();        // O(log n), returns the element directly
pq.front();           // O(1) peek
pq.isEmpty();          // O(1)
pq.size();              // METHOD here — needs ()
📌 dequeue()/front() return the element directly — e.g. const [dist, node] = pq.dequeue().

4 · 🔢 Math.max / Math.min

Math.max(1, 5, 3);        // ✅ individual args → 5
Math.max([1, 5, 3]);       // ❌ NaN
Math.max(...[1, 5, 3]);    // ✅ spread the array
📌 .size/.length = properties (no parens). PQ's .size() = method (needs parens) — the one exception to watch for. Math.max/min never take an array directly — always spread it.

5 · 🚨 Map Access: .get()/.set() ONLY — Never Bracket Notation

const m = new Map<string, number>();
m.set('a', 1);

m.get('a');    // ✅ 1
m['a'];        // ❌ undefined — does NOT read from the Map's data
m['a'] = 5;    // ❌ sets a regular object PROPERTY named "a", not a Map entry
📌 map[key] silently does NOT throw and does NOT touch the Map's actual key-value data — always use .get(key) / .set(key, val) / .has(key), never bracket notation, on a Map.

6 · 🚨 Backtracking: res.push(path) Saves a REFERENCE — Push a Copy

const res: number[][] = [];
const path: number[] = [];

function dfs(start: number) {
    res.push(path);        // ❌ saves the SAME array every time
    res.push([...path]);   // ✅ saves a snapshot of the path right now
    for(let i = start; i < n; i++) {
        path.push(nums[i]);
        dfs(i + 1);
        path.pop();         // backtracking keeps changing that one array
    }
}
🚨 Arrays are passed by reference. res.push(path) stores a pointer to the one path array, not its contents. Every pop() afterwards changes all the "saved" answers too — at the end, every entry in res is the same (usually empty) array, e.g. [[],[],[],[]].
📌 When saving a backtracking answer, always push a COPY: res.push([...path]) (or path.slice()). Same rule for strings built in an array: res.push(path.join('')) already makes a new value.

7 · 🔢 Big Numbers: Number Is Exact Only Up to 15 Digits — Beyond That, BigInt

Number.MAX_SAFE_INTEGER;               // 9007199254740991 = 2^53 − 1 → 16 digits
Number("12345678901234567890");        // ❌ 12345678901234567000 — silently wrong, no error

BigInt("12345678901234567890") + 1n;   // ✅ exact at any length
BigInt(a) + BigInt(b) === BigInt(c);   // ✅ LC 306 Additive Number check

✅ When to reach for BigInt:

  • Numbers arrive as strings longer than 15 digits — LC 306 Additive Number, 415 Add Strings, 43 Multiply Strings
  • A sum or product can grow past ~9 × 10^15
  • Can I use it on LeetCode (e.g. 306)? Yes — LeetCode's JavaScript runs on Node, which supports BigInt.
🚨 BigInt traps 1n + 2 → TypeError (can't mix BigInt and Number — write 1n + 2n) · 7n / 2n → 3n (drops the fraction) · Math.max(1n, 2n) → TypeError (Math.* doesn't take BigInt).

"Without BigInt?" → add the two strings digit by digit from the right, carrying 1 (LC 415).

📌 ≤ 15 digits → Number is fine. 16+ digits → BigInt (or string addition if BigInt isn't allowed). Never mix n numbers with plain numbers.
