2 · 🔵 Set

const s = new Set<number>();
s.add(5); s.has(5); s.delete(5);
s.size;   // PROPERTY, no ()
for (const v of s) {}
[...s];   // to array

new Set([1, 2, 3]);   // ✅ needs an ARRAY
new Set(1, 2, 3);      // ❌ TypeError

3 · 🚨 .keys() / .values() / .entries() Give an ITERATOR, Not an Array — on Map, Set AND Array

.keys().values().entries()
Mapkeysvalues[key, value]
Setsame as valuesvalues[v, v]
Arrayindexesvalues[index, value]
m.keys().sort((a, b) => a - b);        // ❌ iterator has no .sort()
[...m.keys()].sort((a, b) => a - b);   // ✅ spread first
Array.from(m.values());                // ✅ same idea
Object.entries(obj);                   // ⚠️ plain object: a function, returns a real ARRAY
🚨 No .sort(), .map() or .filter() on an iterator. A bare Set is the same: iterable, not an array. And .sort() with no comparator sorts as STRINGS (10 before 2) — pass (a, b) => a - b.
📌 Three methods, one rule: keys / values / entries → iterator. [...x] or Array.from(x) BEFORE any array method. Only Object.keys/values/entries(obj) hands back an array.

4 · 🏗️ MinPriorityQueue / MaxPriorityQueue (LeetCode's built-in library)

const pq = new MinPriorityQueue<number>();                    // simple numeric
const pq = new MinPriorityQueue<number[]>(x => x[0]);          // callback extracts comparison key
const pq = new MaxPriorityQueue<number[]>(x => x[0]);           // reverse order, same API

pq.enqueue(item);   // O(log n)
pq.dequeue();        // O(log n), returns the element directly
pq.front();           // O(1) peek
pq.isEmpty();          // O(1)
pq.size();              // METHOD here — needs ()
📌 dequeue()/front() return the element directly — e.g. const [dist, node] = pq.dequeue().

5 · 🔢 Math.max / Math.min

Math.max(1, 5, 3);        // ✅ individual args → 5
Math.max([1, 5, 3]);       // ❌ NaN
Math.max(...[1, 5, 3]);    // ✅ spread the array
Math.max(...hugeArr);       // ❌ RangeError around 100k+ items (engine-dependent) → use a loop
📌 .size/.length = properties (no parens). PQ's .size() = method (needs parens) — the one exception to watch for. Math.max/min never take an array directly — always spread it.

6 · 🚨 Map Access: .get()/.set() ONLY — Never Bracket Notation

const m = new Map<string, number>();
m.set('a', 1);

m.get('a');    // ✅ 1
m['a'];        // ❌ undefined — does NOT read from the Map's data
m['a'] = 5;    // ❌ sets a regular object PROPERTY named "a", not a Map entry
📌 map[key] silently does NOT throw and does NOT touch the Map's actual key-value data — always use .get(key) / .set(key, val) / .has(key), never bracket notation, on a Map.

7 · 🔢 Big Numbers: Number Is Exact Only Up to 15 Digits — Beyond That, BigInt

Number.MAX_SAFE_INTEGER;               // 9007199254740991 = 2^53 − 1 → 16 digits
Number("12345678901234567890");        // ❌ 12345678901234567000 — silently wrong, no error

BigInt("12345678901234567890") + 1n;   // ✅ exact at any length
BigInt(a) + BigInt(b) === BigInt(c);   // ✅ LC 306 Additive Number check

✅ When to reach for BigInt:

  • Numbers arrive as strings longer than 15 digits — LC 306 Additive Number, 415 Add Strings, 43 Multiply Strings
  • A sum or product can grow past ~9 × 10^15
  • Can I use it on LeetCode (e.g. 306)? Yes — LeetCode's JavaScript runs on Node, which supports BigInt.
🚨 BigInt traps 1n + 2 → TypeError (can't mix BigInt and Number — write 1n + 2n) · 7n / 2n → 3n (drops the fraction) · Math.max(1n, 2n) → TypeError (Math.* doesn't take BigInt) · BigInt(1.5) → RangeError · 1n / 0n → RangeError · JSON.stringify(1n) → TypeError.

🛠️ Using it:

const nums = strs.map(s => BigInt(s));           // convert once, up front
arr.sort((a, b) => (a < b ? -1 : a > b ? 1 : 0)); // ❌ a - b throws TypeError
new Map<bigint, number>();                        // keys match by value ✅
x.toString();                                     // return huge answers as strings
BigInt.asIntN(64, x);                             // imitate a 64-bit long

"Without BigInt?" → add the two strings digit by digit from the right, carrying 1 (LC 415).

📌 ≤ 15 digits → Number is fine. 16+ digits → BigInt (or string addition if BigInt isn't allowed). Never mix n numbers with plain numbers.

8 · 🚨 new Array(n).fill([]) — Every Row Is the SAME Array

const g = new Array(3).fill([]);
g[0].push(1);                                   // ❌ [[1],[1],[1]] — one array shared by all rows
const g = Array.from({length: 3}, () => []);    // ✅ a fresh array per row
📌 .fill(x) copies the REFERENCE. fill(0) is fine (numbers), fill([]) / fill({}) is not. 2D DP: Array.from({length: m}, () => new Array(n).fill(0)).

9 · 🚨 Arrays as Set/Map Keys Compare by REFERENCE — Use a String Key

const seen = new Set<number[]>();
seen.add([0, 1]);
seen.has([0, 1]);                 // ❌ false — a different array object

const seen = new Set<string>();
seen.add(`${r},${c}`);
seen.has(`${r},${c}`);            // ✅ true — strings compare by value
📌 Visited cells in a grid: key = `${r},${c}`, or the number r * cols + c (faster). Same rule for Map keys.

10 · 🔤 Strings Are Immutable — s[i] = 'x' Does Nothing

s[0] = 'z';                                  // ❌ silently ignored (TypeError in strict mode)
const a = s.split(''); a[0] = 'z'; a.join('');   // ✅ edit as an array, join back
s.charCodeAt(i) - 97;                        // letter → index ('a' = 0 … 'z' = 25)
String.fromCharCode(97 + k);                 // index → letter
📌 Need to change a string? split('') → edit → join(''). Building one piece by piece? Push to an array, join once at the end.

11 · 🔢 Integer Math: % and / With Negatives, and 32-bit Bit Ops

-1 % 5;                  // ❌ -1, not 4 — % keeps the sign of the LEFT side
((x % n) + n) % n;       // ✅ always 0…n-1 (circular index, hashing)
Math.floor(-7 / 2);      // -4 — rounds down
Math.trunc(-7 / 2);      // -3 — cuts the decimal (what Java/C++ `/` does)
1 << 31;                 // -2147483648 — bit ops work on 32-bit signed ints
📌 a / b is a float — wrap it: Math.floor for positives, pick floor vs trunc on purpose for negatives. | & ^ << >> cut numbers to 32 bits: fine up to 2^31, wrong beyond it.

12 · 🐢 queue.shift() Is Slow on Big Arrays — BFS With a Head Pointer

while (q.length) { const x = q.shift(); }          // ❌ each shift moves every element → O(n)

let head = 0;
while (head < q.length) { const x = q[head++]; }   // ✅ O(1) per pop, push() still works
📌 Measured on Node 22: 200k shift() calls took ~3.5 s, the head pointer ~1 ms. Use q[head++] for BFS queues.

13 · 🆚 Object vs Map as a Dictionary — Use Map for Counting

const o: any = {}, m = new Map()
o[1] = 'a'; o['1'] = 'b'         // 1 key: both become "1"
m.set(1, 'a'); m.set('1', 'b')   // 2 keys: types kept

count['constructor'] = (count['constructor'] || 0) + 1   // ❌ starts from a function, not 0

📋 Order: a Map is strictly insertion order. An Object puts integer-like keys first, sorted: keys b, a, 2, 1 come out as 1, 2, b, a. (Map access is #6.)

📌 Object keys are always strings and come with inherited names (constructor, toString). Map keeps types and insertion order. For counting, or any key you don't control, use Map.

14 · 🔤 Alphanumeric Check — a One-Character Helper (Valid Palindrome)

function isAlphaNumeric(ch: string) {
    const c = ch.toLowerCase();

    return (c >= 'a' && c <= 'z') || (c >= '0' && c <= '9');
}
// shorter: /[a-z0-9]/i.test(ch)
📌 Pass ONE character. Lowercase first, so one range covers A–Z. Use it to skip junk in two-pointer string problems (LC 125).
