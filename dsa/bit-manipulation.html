🧠 1 · How to think (and invent it)

An integer is just bits indexed from the right. Three mental models cover almost everything: an int is a bitset (each bit = a flag / set member); XOR is a toggle that cancels itself; and a mask (AND with a chosen pattern) selects bits. Master a handful of idioms and these problems become one-liners.

The single most useful property: a ^ a = 0 and a ^ 0 = a, and XOR is order-independent. So XOR-ing a pile of numbers makes every pair vanish — whatever's left is the odd one out.

Watch it get invented — Single Number

  1. Start brute. Every value appears twice except one. A hash-map count finds it — but in O(n) extra space.
  2. The leap. XOR everything. Identical values cancel in pairs (a ^ a = 0), and order doesn't matter, so the duplicates annihilate and only the unique value survives.
  3. Payoff. One pass, O(1) space, no map.
The two idioms that print money n & (n − 1) clears the lowest set bit → test power-of-two (=== 0) and count bits (Kernighan). n & (−n) isolates the lowest set bit. Recognize these two and a huge fraction of bit problems collapse.

🧩 4 · The four core patterns

§4.1 is a vocabulary you memorize; §4.2–4.4 apply it. Each: a one-liner, a 🔑 invariant, a template, a 🎤 interview lens.

4.1 · The idiom toolkit

“Mask to select, shift to move, AND-with-(n−1) to peel the lowest bit.”

🔑 Invariant — why n & (n−1) works Subtracting 1 flips the lowest set bit to 0 and all the zeros below it to 1; ANDing with the original keeps every higher bit and wipes that lowest run — netting exactly "remove the lowest set bit." Repeating it touches each set bit once.
const getBit   = (n: number, i: number) => (n >> i) & 1;
const setBit   = (n: number, i: number) => n | (1 << i);
const clearBit = (n: number, i: number) => n & ~(1 << i);
const toggleBit= (n: number, i: number) => n ^ (1 << i);

const isPowerOfTwo = (n: number) => n > 0 && (n & (n - 1)) === 0;   // one set bit
const lowestSetBit = (n: number) => n & (-n);                      // isolate it
const clearLowest  = (n: number) => n & (n - 1);                   // remove it

// Count set bits — Brian Kernighan: loops once per 1-bit
function popcount(n: number): number {
  let c = 0;
  while (n) { n &= n - 1; c++; }
  return c;
}
🎤 Interview lens Probed: derive n & (n−1) and n & −n on the spot; the JS 32-bit / precedence caveats. · Escalation: idioms → "Counting Bits" (DP: dp[i] = dp[i & (i−1)] + 1) → a Fenwick/BIT tree (whose jumps use n & −n).

4.2 · XOR tricks

“XOR everything; pairs cancel, the loner survives.”

🔑 Invariant — why it's safe XOR is commutative and associative with a ^ a = 0, a ^ 0 = a. So any value appearing an even number of times contributes nothing to the running XOR; the accumulated result is exactly the XOR of the odd-count values.
// Single Number — every value twice except one
const singleNumber = (nums: number[]) => nums.reduce((a, b) => a ^ b, 0);

// Missing Number in [0..n] — XOR the indices and the values together
function missingNumber(nums: number[]): number {
  let x = nums.length;
  for (let i = 0; i < nums.length; i++) x ^= i ^ nums[i];   // every present value cancels
  return x;
}

// Single Number III — exactly TWO values appear once, the rest twice
function singleNumberIII(nums: number[]): number[] {
  const xorAll = nums.reduce((a, b) => a ^ b, 0);   // = a ^ b  (the two loners)
  const diff = xorAll & (-xorAll);                   // a bit where a and b differ
  let a = 0;
  for (const x of nums) if (x & diff) a ^= x;        // partition by that bit → isolates a
  return [a, a ^ xorAll];                            // b = (a^b) ^ a
}
🎤 Interview lens Probed: the self-cancel properties and O(1) space; for III, why a differing bit cleanly splits the two loners. · Escalation: single → missing → single number III → single number II (every value thrice except one: count bits mod 3).

4.3 · Bitmask — an int as a set

“Bit i set = item i chosen; loop 0…2ⁿ−1 to walk every subset.”

Setup: for small n, a state (which items are picked / visited) fits in one integer. Enumerate all subsets by counting, test membership with a mask, and compress DP state into the int.

🔑 Invariant — why it's complete The integers 0 … 2ⁿ−1 are in bijection with the subsets of an n-element set (bit i = "item i included"). So iterating that range visits every subset exactly once; the submask trick (sub − 1) & mask walks exactly the subsets of a given mask.
// All subsets of items[0..n-1]
function subsets<T>(items: T[]): T[][] {
  const n = items.length, out: T[][] = [];
  for (let mask = 0; mask < (1 << n); mask++) {
    const pick: T[] = [];
    for (let i = 0; i < n; i++) if (mask & (1 << i)) pick.push(items[i]);
    out.push(pick);
  }
  return out;
}

// Enumerate every submask of `mask` (for bitmask DP over subsets)
function submasks(mask: number): number[] {
  const out: number[] = [];
  for (let sub = mask; sub > 0; sub = (sub - 1) & mask) out.push(sub);
  out.push(0);
  return out;
}
🎤 Interview lens Probed: the set↔int mapping, subset/submask enumeration, and the n ≲ 20 feasibility limit. · Escalation: subsets → bitmask DP over states ("Partition to K Equal Subsets", assignment, the TSP dp[mask][i]).

4.4 · Bit arithmetic — add without +

“Sum-without-carry is XOR; the carry is AND shifted left; repeat.”

Setup: binary addition splits into two parts — the column sum ignoring carries (a ^ b) and the carries themselves ((a & b) << 1). Fold the carry back in until it's gone.

🔑 Invariant — why it terminates a ^ b is the partial sum and (a & b) << 1 are the bits that must carry one place up. Each iteration moves carries strictly leftward, so after at most word-size rounds the carry becomes 0 and a holds the exact sum.
// Sum of Two Integers without + or -
function getSum(a: number, b: number): number {
  while (b !== 0) {
    const carry = (a & b) << 1;   // where both bits are 1 → carry up
    a = a ^ b;                    // add the columns, ignoring carry
    b = carry;                    // now add the carry in
  }
  return a;
}

⚠️ 6 · Pitfalls — and the test that catches each

BugThe input that exposes it
Operator precedence: & | ^ bind looser than == + .n & 1 === 0 parses as n & (1 === 0) → always falsy. Parenthesize: (n & 1) === 0.
JS bitwise is 32-bit signed.1 << 31 is negative; values ≥ 2³¹ break. Use >>> 0 or BigInt.
>> (sign-extend) vs >>> (zero-fill).-8 >> 1 = -4 but -8 >>> 1 is a huge positive — pick deliberately.
Shift amount ≥ word size is undefined / wraps.1 << 32 in JS is 1 (shift is mod 32), not 0.
Bitmask: indexing with i instead of 1 << i.Any subset enumeration → wrong members selected.
Assuming Kernighan loops 32 times.Sparse numbers (one set bit) → it loops once; don't hard-code 32 unless you mean it.
