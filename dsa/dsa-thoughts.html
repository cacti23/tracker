1 · 🚦 Which Shortest-Path Tool?

EdgesUse
All cost 1🟢 BFS
Different weights, all ≥ 0🔵 Dijkstra (#5)
Negative weights, or "at most K stops"🟠 Bellman-Ford (#9)
Every pair of nodes🟣 Floyd-Warshall (#10)
Connect everyone cheapest (not a path)🌲 Kruskal's MST (#11)

Why BFS breaks with weights: BFS trusts "visited first = shortest". 📐 start→A costs 10, start→B→A costs 1+1 = 2. BFS reaches A first by the direct edge, locks in 10, and the cheaper path via B is blocked.

📌 Weight-1 edges → BFS. Any other weights → "visited first" no longer means shortest → Dijkstra.

2 · 🎯 Seed the Start Before the Loop (BFS + Dijkstra)

Unweighted → BFS. Weighted, non-negative weights → Dijkstra. Both need the start set up before the loop.

// BFS
queue = [start]; visited.add(start);   // mark when you push, not when you pop
// Dijkstra
dist.fill(Infinity); dist[src] = 0; pq.enqueue([0, src]);
⚠️ Forget to mark start visited → a neighbour pushes it again. Forget dist[src] = 0 → every distance stays Infinity.
📌 Before the loop: start is in the queue, marked, with distance 0. Mental swap: BFS → visited, Dijkstra → dist[] = ∞.

5 · 🎯 Dijkstra — Skip Stale Entries, TC = O(E log E)

dist[node] = cheapest cost found so far. A node can sit in the heap several times (once per cheaper path found), so skip the old ones:

if (currTime > dist[node]) continue   // stale: a cheaper path already won

⏱️ TC, counted from relaxations (not from V+E):

  • A node is expanded for real only once, so each edge is checked once → at most E pushes.
  • Heap holds up to E entries → each push/pop is log E.
  • Total O(E log E). Same as O(E log V), since E ≤ V² makes log E ≤ 2 log V.
📌 Act only on a node's lowest known cost. TC = (how many times an edge can relax) × (cost per relax): Dijkstra E × log E, Bellman-Ford V × E (every edge, up to V−1 rounds).

6 · ⏳ 2577 vs 3341/3342 — Can You Wait, or Must You Move?

🎯 All THREE use Dijkstra. The ONE difference: can you WAIT in place?

🚨 2577 (Minimum Time to Visit a Cell in a Grid): NO waiting. Forced to move every step. Arriving too early → must BOUNCE (move away, come back) to kill time → needs PARITY math:
if (neiTime <= currTime+1) nextTime = currTime+1
else if ((neiTime-currTime)%2===0) nextTime = neiTime+1
else nextTime = neiTime

⚠️ Special case: (0,0) has NO parent to bounce with. If BOTH its neighbors need >1 to enter, you're stuck immediately:

if (grid[0][1]>1 && grid[1][0]>1) return -1

✅ 3341/3342 (Reach Last Room I/II): FREE waiting. Just sit and wait, then move:

nextTime = max(currTime, moveTime[nr][nc]) + moveCost
🔑 3341 vs 3342 only the move cost differs: 3341 = fixed +1. 3342 = alternates +1/+2 based on (row+col)%2.
📌 Can't wait → bounce + parity math (2577, plus the (0,0)-no-parent edge case). Can wait → simple max()+cost (3341/3342).

7 · 🎯 "Group + Delete-Once" Kills Repeated O(n) Scans in BFS

🎯 When: in a BFS, one node can jump to MANY nodes that share a key (same value, same prime factor). Re-scanning the whole array from each such node is O(n²).

📐 LC 3629 (Prime Teleportation): jump i±1, or, when nums[i] is a prime p, to any j with nums[j] % p === 0.

✅ Fix: build the buckets once, and delete a bucket the first time you use it:

// prime -> [indices whose value has this prime factor], built once before BFS
const nextIdxs = primeToIdx.get(currVal)
for (const idx of nextIdxs ?? []) { /* visit */ }
primeToIdx.delete(currVal)   // every index in it is already queued

📊 Why O(n log maxVal): each bucket is read once in the whole BFS, so total work = sum of bucket sizes. A number with k distinct primes is ≥ 2^k, so k ≤ log₂(maxVal) buckets per number.

📌 Many nodes linked by a shared key → bucket by key, delete after first use. Work = sum of bucket sizes, not nodes × scan.

8 · 🎯 Binary Search + BFS vs Binary Search + Dijkstra

🎯 "Can I reach X using only edges ≤ mid?" → BFS. "What's the CHEAPEST path?" → Dijkstra.

🔑 Binary search already picked the max allowed weight and filtered the graph, so the check only needs YES/NO reachability.

📐 LC 3419 (minimize the max edge weight so every node can reach node 0): check(mid) = keep edges ≤ mid, reverse them, BFS from 0, did it reach every node? No distances needed.

📌 Dijkstra finds the CHEAPEST path. BFS finds IF a path exists. Binary-search-on-threshold problems usually only need the second.

9 · 🟠 Bellman-Ford — Negative Weights or K Stops

🚨 Negative weights → Bellman-Ford, not Dijkstra. Dijkstra is greedy ("once finalized, always correct"), and a later negative edge can break a finalized distance.

🔁 Negative cycle check: run one extra round after V−1. Anything still improves → negative cycle.

🎯 "At most K stops" (no negatives needed, LC 787): K stops = K+1 rounds. Dijkstra can't cap the edge count without adding it to its state.

for (let round = 0; round <= k; round++) {
  const prev = [...dist]                    // read last round only
  for (const [u, v, w] of flights)
    if (prev[u] + w < dist[v]) dist[v] = prev[u] + w
}
⚠️ Without the prev copy, one round can chain several edges and break the K limit. LC 787 example (k = 1): copy → 700 ✅, no copy → 400 ❌.

🔗 Undirected: non-negative → add u→v and v→u, run as normal. One negative undirected edge = a negative cycle by itself (bounce u→v→u forever).

📌 Negatives or "at most K edges" → Bellman-Ford, O(V·E). For K stops, relax from a copy each round.

10 · 🌊 Floyd-Warshall — Every Pair at Once

🎯 Shortest distance between EVERY pair of nodes, not just from one source.

dist[i][i] = 0, everything else Infinity
dist[u][v] = Math.min(dist[u][v], w)   // per edge; set dist[v][u] too if undirected

for k in 0..n:        // MUST be outermost: try every "middle stop"
  for i in 0..n:
    for j in 0..n:
      if dist[i][k]+dist[k][j] < dist[i][j]:
        dist[i][j] = dist[i][k]+dist[k][j]

⚠️ Math.min at init only matters when the input can repeat an edge between the same pair, but it is never wrong, so keep it as a habit. The main loop's if already keeps the smaller value.

📌 k outermost, always. Undirected = set both directions at init. O(V³).

11 · 🕸️ Minimum Spanning Tree — Master Kruskal's, Skip Prim's

🎯 Connect ALL nodes (directly or through others) with the MINIMUM TOTAL edge cost. Not "shortest path between two nodes": that's Dijkstra, a different question. Dijkstra adds up distance from a source; MST doesn't care about distance from anywhere.

Problems: LC 1584 Min Cost to Connect All Points, LC 1135 Connecting Cities With Minimum Cost.

🔑 Kruskal's and Prim's give the same MST. Master Kruskal's: sort edges, add the cheapest one that doesn't make a cycle (Union-Find, same as cycle detection, removeStones, magnificentSets). Prim's: just know it exists.
// general MST: n nodes, edges = [u, v, weight]
function minCostToConnectAllNodes(n: number, edges: number[][]): number {
    const parent = Array.from({ length: n }, (_, i) => i);
    const rank = Array(n).fill(0);

    function find(x: number): number {
        let root = x;
        while (parent[root] !== root) root = parent[root];
        while (parent[x] !== root) {
            const next = parent[x];
            parent[x] = root;
            x = next;
        }
        return root;
    }

    function union(x: number, y: number): boolean {
        const px = find(x), py = find(y);
        if (px === py) return false;
        if (rank[px] < rank[py]) parent[px] = py;
        else if (rank[px] > rank[py]) parent[py] = px;
        else { parent[px] = py; rank[py]++; }
        return true;
    }

    edges.sort((a, b) => a[2] - b[2]); // sort by weight ascending

    let totalCost = 0, edgesUsed = 0;

    for (const [u, v, weight] of edges) {
        if (union(u, v)) {
            totalCost += weight;
            edgesUsed++;
            if (edgesUsed === n - 1) break; // tree complete
        }
    }

    return edgesUsed === n - 1 ? totalCost : -1; // -1 if graph can't be fully connected
}
📌 MST (Kruskal's) = cheapest way to connect EVERYONE. Dijkstra = cheapest path from ONE source. Different questions.

12 · 🔄 Cycle Detection — All Methods, At a Glance

🔗 UNDIRECTED — 3 ways

1. DFS + parent-skip:

dfs(node, parent):
  visited[node] = true
  for nei in graph[node]:
    if nei === parent: skip
    if visited[nei]: CYCLE
    dfs(nei, node)

2. BFS + parent-skip: same idea, queue holds (node, parent) pairs instead of recursion.

🚨 Always both BFS/DFS on an undirected graph ALWAYS needs visited + parent. visited finds the cycle (a second path to a seen node). parent stops a false alarm: edge u–v is stored both ways, so v always sees u as visited. Duplicate edges (u–v twice)? Skip the parent edge id, not the parent node.

3. Union-Find:

for each edge (u,v):
  if find(u) === find(v): CYCLE
  else union(u,v)

➡️ DIRECTED — 2 ways (Union-Find does NOT apply — no sense of direction)

1. DFS with 0/1/2 marking:

state: 0=unvisited, 1=exploring, 2=done
dfs(node):
  state[node] = 1
  for nei in graph[node]:
    if state[nei]===1: CYCLE (back edge to node still exploring)
    if state[nei]===0: dfs(nei)
  state[node] = 2

2. Kahn's (BFS topological sort): keep peeling nodes with indegree 0. Nodes on a cycle never reach 0.

queue = all nodes with indegree 0
process queue, decrementing neighbors' indegree, adding new indegree-0 nodes
if processedCount < n: CYCLE (leftover nodes stuck in a cycle)
📌 Undirected → DFS/BFS parent-skip or Union-Find. Directed → 0/1/2 DFS or Kahn's (processed < n → cycle). Union-Find can't tell direction, so it can't detect directed cycles.

13 · 🌳 Valid Tree — Just Two Rules: Connected + No Cycle

🎯 Any tree (binary, ternary, any number of children) is valid when:

  1. 🔗 Connected: one component, every node reachable
  2. 🚫 No cycle

Binary vs ternary only limits children per node. It doesn't change what makes it a tree.

🛠️ How to check:

  • Undirected edges (LC 261): exactly n − 1 edges + connected (no cycle follows from that)
  • Parent pointers (LC 1361): each node has ≤ 1 parent, exactly one root (0 parents), all reachable from the root
📌 Tree = connected + no cycle. Everything else is a way to count it.

14 · ✈️ Hierholzer's — Every Edge Once, TC = O(E)

🎯 Eulerian path = use every EDGE once, not every node. Push the node to the result on the way OUT (post-order), then reverse at the end.

⏱️ TC = O(E), not V+E: each edge is removed once (graph[node].pop()). A node is visited once per outgoing edge, so counting nodes separately adds nothing.

🚨 Why post-order? (LC 332 Reconstruct Itinerary)

➡️ Add an airport to res ONLY after all its tickets are used. The first time you get stuck, you are at the final stop, so the stuck node goes in first. res builds the trip backwards → reverse at the end.

tickets: JFK→A, JFK→B, B→JFK
(smallest first: A before B)

❌ pre-order (add on arrival)
   JFK → A → B → JFK
   no ticket A→B! A written too early

✅ post-order
   res = [A, JFK, B, JFK]
   reverse → JFK → B → JFK → A
⚠️ Pre-order passes both LC 332 examples (no dead ends there). It fails when the smallest choice leads to a dead end before all tickets are used, like A above.
📌 DFS that consumes each edge once → O(E). 🧠 Dead end = finish line → write it first, read it backwards.

15 · ⚖️ V+E Is a Shortcut — Only Safe When Work Is O(1)

🎯 V+E really means V × (work per node) + E × (work per edge).

✅ Work per node/edge is O(1) (a comparison, a neighbour check) → just write V+E.

🚨 Work is more than O(1) (building a string, hashing it) → multiply it in.

📐 Example — removeInvalidParentheses (n = string length): up to 2^n states, each makes up to n children (edges), and each child is an O(n) string slice.

Total = 2^n states × n children × O(n) slice = O(2^n · n²)
📌 Check the cost of ONE unit of work first. O(1) → V+E. O(k) → multiply k in.

16 · 📊 How Many Edges? Grid, Dense, Sparse, Tree

Grid M×N:  V = MN, E ≤ 4MN  → V+E = O(MN)   (the 4 drops)
Dense:     E = O(V²)        ← max for a simple graph
Sparse:    E = O(V)
Tree:      E = V − 1        ← always sparse

🎯 Values between V and V² exist (V log V, V√V), but interviews only need the two bounds. Union-Find follows the same split: O(E · α(V)) → sparse ≈ O(V), dense ≈ O(V²).

🚨 Sparse ≠ tree. A tree is one kind of sparse graph.
📌 Tree ⊂ Sparse ⊂ Graph. Grid BFS/DFS → O(MN).

18 · 🚨 1-Indexed Node Labels → EVERY Reference Needs the Same -1, Including the Source

🎯 Nodes labeled 1..n but arrays built 0..n-1 → every node from the input gets -1, not just the edges. The start node k is the one that gets forgotten, because it sits outside the edge loop.

for (const [u, v, w] of times) graph[u - 1].push([v - 1, w])   // converted

pq.enqueue([0, k]); dist[k] = 0           // ❌ k still 1-indexed
pq.enqueue([0, k - 1]); dist[k - 1] = 0   // ✅

📐 Silent, not loud: the wrong node gets distance 0, and when k === n, dist[k] is out of bounds and JS doesn't throw (JS Gotchas #1). You usually see a wrong -1 ("unreachable"), not a crash.

📌 Convert EVERY input label the same way. Check the source/target parameters outside the edge loop.

3 · 🌳 Tree Traversal as Undirected Graph — Parent Map

Trees only give CHILD pointers (left/right) — no way UP.

🎯 Don't build a full adjacency-list graph — just add the ONE missing piece: parent.

📐 One DFS pass, passing (node, parent), building parentMap.set(node, parent).

🔑 Then treat the tree as undirected: left, right, AND parentMap.get(node) = 3 directions.

Used for: All Nodes Distance K in Binary Tree (863) — any problem needing "go up" in a tree.

4 · 🍎 Collect Items in a Tree — dfs Returns "Has Item?", Not Time

🎯 Don't make dfs return "time to reach here". Return does this subtree have an apple? A child says yes → you must walk that edge down and back → totalTime += 2 (LC 1443).

// dfs(node, parent) -> tell if subtree has apple or not
let currTreeHasApple = hasApple[node]
for (const nei of graph[node]) {
    if (nei === parent) continue
    if (dfs(nei, node)) { totalTime += 2; currTreeHasApple = true }
}
return currTreeHasApple
⚠️ A subtree with no apple costs 0, you never walk into it. Returning "time" pushes you to add paths you don't need.

⏱️ TC O(n): each node once (parent guard), edges scanned once in total, E = n − 1. SC O(n): adjacency list + recursion stack (path-shaped tree).

📌 Collect things in a tree and come back → dfs returns "is anything needed below?", each needed edge costs 2.

1 · ↕️ Return Up vs Push Down — Where Does the Answer Travel?

🎯 Recursion has two ways to get an answer out, and many problems work with either. 🔙 Return up: dfs returns the answer "from here" and the parent combines it. ⬇️ Push down: dfs returns nothing, carries state in its parameters, and records the answer at the base case. (DP #1's "Read 1 = what I RETURN" is the return-up style.)

🔙 Return up⬇️ Push down
Function returnsa value (max, sum, count)void
Answer lives inthe top call's return valuean outer variable (best, count++, res.push)
Natural forone number: max / min / count / yes-no. Memoizes easily (the subproblem is just the arguments)every path, or a rule like "visited all zero cells"
Params holdonly what's LEFT to decide (row, prevCol)the past too (currSum, path)
Memo works?✅ yes → DP❌ no → stays brute force
// Gold (LC 1219) as PUSH DOWN: carry the sum, update an outer variable
sum += grid[r][c];
best = Math.max(best, sum);                                // answer collected on the way down

// Paths III (LC 980) as RETURN UP: base case returns 1 or 0, parent adds
if (grid[r][c] === 2) return zeroCount === 0 ? 1 : 0;

🧪 Parameter test: before adding a parameter, ask "does the FUTURE need this to decide?" Yes (row, prevCol) → it's state, keep it. No, it only records the past (currSum) → drop it and return the answer instead. Two paths reach the same (row, prevCol) with different sums, so with currSum in the params nothing repeats and a memo never hits. (Same idea as DP #1: small carry → memoize.)

// Falling Path Sum II (LC 1289)
// ⬇️ push down: currSum is the past → no memo
dfs(row + 1, col, currSum + grid[row][col]);

// 🔙 return up: state = (row, prevCol) → memo → O(m·n²)
best = Math.min(best, grid[row][col] + dfs(row + 1, col));

❓ Pick with one question: "What does dfs(state) mean?" → "the answer for the subproblem from here" = return up. "I'm here with this path so far, report when you arrive" = push down.

♻️ Same rule in both: if you mutate a shared grid, undo before you return.

📌 Return = answers climb UP the stack 🪜. Push = state walks DOWN the stack 🚶. Params = what's LEFT to decide, not what already happened. Only need a number → return up (memo → DP). Need every path → push down (backtracking).

2 · 🎯 Sentinel-Seeding: When It's Safe vs When It's Not

🎯 The REAL question: does my function have an EXPLICIT base case, or is the "seed value" secretly ACTING as the base case?

✅ Explicit base case exists (if(...) return 0; / a clean, dedicated return) → sentinel-seeding is SAFE, don't overthink it. The base case ALWAYS overrides the sentinel with a real answer.

function dfs(row, col) {
    if (invalid) return 0;          // explicit base case, resolves cleanly
    ...
    let maxGold = 0;                 // sentinel is fine, loop always gets overridden
    for (...) maxGold = Math.max(maxGold, dfs(...));
    return currGold + maxGold;       // add currGold ONCE, here
}
🚨 NO explicit base case (a "dead end" is just "the loop found nothing," no dedicated return) → the SEED value ITSELF is the base case's answer. It MUST equal the correct "nothing more to add" result — NOT a generic sentinel.
function dfs(row, col) {
    // no explicit base case — dead end = loop simply doesn't run
    let maxGold = currGold;          // seed = the correct dead-end answer itself
    for (...) maxGold = Math.max(maxGold, currGold + dfs(...));
    return maxGold;
}
📌 Explicit base case → sentinel-seeding is safe, base case always resolves it. NO explicit base case → the seed IS the base case, so it must already equal the correct answer for "nothing more happens here" — not a placeholder.

3 · 🔀 Backtracking — used[], Reuse and Duplicates: Ask 3 Questions Before the Loop

🎯 Before writing any backtracking code, answer three questions in order. Together they decide the whole loop: where it starts, what you recurse with, and whether you need used[] or a skip.

1️⃣ Does order matter?

Test with a tiny example: is [1,2] the same answer as [2,1]?

  • Different (order matters) → 🔴 Permutation → loop starts from 0 every call (any element can follow any element)
  • Same (order doesn't matter) → 🟢 Subset / Combination → loop starts from start (never look back at earlier indices)
🚨 Problem names LIE. "Combination Sum IV" is actually a PERMUTATION problem — LeetCode counts [1,2] and [2,1] as 2 separate ways, not 1. Trust the tiny example, not the title.

2️⃣ Can an element be reused?

// Combination: reuse is decided by what you recurse with
for(let i = start; i < n; i++) dfs(i, ...);       // reuse allowed  (Combination Sum)
for(let i = start; i < n; i++) dfs(i + 1, ...);   // no reuse       (Combination Sum II, Subsets)

// Permutation, NO reuse: used[] blocks an element already on the path (Permutations)
for(let i = 0; i < n; i++) {
    if(used[i]) continue;
    used[i] = true;
    path.push(nums[i]);
    dfs();
    path.pop();
    used[i] = false;
}

// Permutation, reuse allowed: no used[] at all (Combination Sum IV)
for(let i = 0; i < n; i++) dfs(...);
🚨 A permutation loop from 0 WITHOUT used[] lets the same element be picked again. That's right for Combination Sum IV, but in plain Permutations [1,2,3] it produces [1,1,1].

3️⃣ Does the input have duplicate values?

Sort first, then skip a repeated value at the SAME level of the tree:

nums.sort((a, b) => a - b);

// Combination / Subset (Subsets II, Combination Sum II)
if(i > start && nums[i] === nums[i - 1]) continue;

🔀 Permutations II (LC 47) — same sort, then two used[] checks:

for(let i = 0; i < n; i++) {
    if(used[i]) continue;                                             // already in my path
    if(i > 0 && nums[i] === nums[i - 1] && !used[i - 1]) continue;    // same value as left twin, twin not in my path
    used[i] = true; path.push(nums[i]);
    backtrack();
    path.pop(); used[i] = false;
}

🔁 Can't sort? Use a LOCAL Set instead (LC 491 Non-decreasing Subsequences — sorting would destroy the subsequence order). Create it INSIDE each call, right before the loop:

const seen = new Set();                        // fresh per call
for(let i = start; i < n; i++) {
    if(seen.has(nums[i])) continue;            // already tried this VALUE at this level
    seen.add(nums[i]);                         // never removed — no undo
    path.push(nums[i]); dfs(i + 1); path.pop();
}
🚨 The Set must be LOCAL (created inside each call): a shared Set would also block [4,7] after [4,6,7] used the 7, which is a different path and must stay allowed.
📌 Order → Reuse → Duplicates. Order picks the loop start (0 or start), reuse picks i vs i + 1 (or used[] for permutations), duplicates add sort + skip. Three answers give you the whole loop.

4 · 🔢 Set → Bitmask — A Set of Small Integers Is ONE Integer

🎯 When the options are small integers (columns 0…n−1, digits 1…9), a Set of them fits in one integer: number x is in the set ⇔ bit x is ON. Same algorithm, cheaper operations. (DP #1 uses a mask to memoize; here it only speeds up plain backtracking.)

bit = 1 << x

set.has(x)      →   mask & bit
set.add(x)      →   mask |= bit
set.delete(x)   →   mask &= ~bit

♟️ N-Queens: 3 Sets → 3 integers

// Set
const cols = new Set<number>()
cols.has(col)
cols.add(col)
cols.delete(col)

// Bitmask
let cols = 0
cols & (1 << col)
cols |= 1 << col
cols &= ~(1 << col)

diag1 and diag2 work exactly the same (with d1 and d2). 🔎 Example: queens in columns 1 and 3 → bits 1010 = 10.

🔢 Sudoku: array of 9 Sets → array of 9 integers

// Set
const rows = Array.from({length: 9}, () => new Set<string>())
rows[r].has('5')

// Bitmask
const rows = new Array(9).fill(0)

rows[r] & bit

🚨 The board holds digit strings ('5'), but a bit position needs a number — convert with Number(ch). Same for cols[9] and blocks[9].
🚨 Gain and limit Same Big-O, about 5x faster in N-Queens (n = 10 to 12, Node 22). A mask holds only bits 0…31: 1 << 32 wraps back to 1. N-Queens diagonals use bits up to 2n−2, so n ≤ 16 is safe and n = 17 breaks.
📌 "Options are small integers, so each Set can be one integer: bit x on means x is taken. Same algorithm, smaller constant."

6 · 🌲 Unmemoized Recursion TC — 3-Question Framework

🎯 Ask these in order. Stop at the first one that fits.

Q1 — Constant branching? (same # choices every call)

→ branches^depth. (take/skip → 2ⁿ)

  • 🧱 Grid, 4 directions → branch≈4, depth≈M×N → O(4^(M×N))
  • ↘️ Grid, right/down only → branch=2, depth=M+N → O(2^(M+N))

Loose bounds — actual cost depends on visited-tracking and work per call.

Q2 — Variable branching, but is there a FIXED set of positions each getting an independent yes/no?

→ 2^(that count).

Stone Game II: n-1 gaps → cut or not → 2^(n-1)
LC 131 Palindrome Partitioning: n-1 gaps → cut or not → 2^(n-1)

Q3 — Branching is a SPLIT POINT choice (pick k, recurse both sides)?

→ Catalan-shaped: dfs(i,j) = Σ dfs(i,k) ⊗ dfs(k,j)

function dfs(i: number, j: number): number {
    if (i >= j) return 1;
    let total = 0;
    for (let k = i; k < j; k++) {
        total += dfs(i, k) * dfs(k + 1, j);   // k = split point
    }
    return total;
}

k = root (96 Unique BST), last-op (241), last-burst (312 Burst Balloons), matrix-split (Matrix Chain Mult — the textbook Catalan recurrence itself).

None of the above fits?

→ Just say "exponential, no clean polynomial form" — honest, accepted answer.

LC 3629 prime teleport (brute force) — branch count varies per index

7 · 🍃 Recursion Tree — bᵈ Counts LEAVES, Not Every Node

🎯 2ⁿ (take/skip) and nᵈ (a for loop inside recursion) are the number of leaves. The tree has more nodes than that, but not a different big-O.

branching b ≥ 2, depth d
leaves = b^d
nodes  = 1 + b + … + b^d = (b^(d+1) − 1) / (b − 1)  ≤ 2·b^d

take/skip:    leaves 2^n,  nodes 2^(n+1) − 1   → still O(2^n)
permutations: leaves n!,   nodes ≈ e·n!         → still O(n!)

📐 Why: the last level is bigger than all the levels above it put together, so it decides the big-O.

⚖️ What actually changes the answer is the work per node:

  • ⚡ O(1) at every node → O(bᵈ)
  • 🍃 Real work only at the leaves (copy a path of length n) → O(n · bᵈ)
  • 🌲 O(n) at every node (slice, copy, join) → also O(n · bᵈ)
🚨 Only a chain (b = 1) breaks "nodes ≈ leaves": 1 leaf but d + 1 nodes. Count nodes only when work per node is not the same everywhere. See #6 for the bᵈ shapes.
📌 TC = (number of nodes) × (work per node). For b ≥ 2, nodes = O(leaves) = bᵈ, so the only thing left to ask is the work at each node.

2 · 🧭 Recursion → DP: Direction and Starting Index Come FROM the Recurrence

🎯 Workflow: write the recursion first, find its recurrence, then read direction + start straight off it — don't guess either one.

Direction — which way does the recurrence point?

dp[i] depends on dp[i+1], dp[i+2]... (LARGER index) → loop i: n-1 DOWN TO 0
dp[i] depends on dp[i-1], dp[i-2]... (SMALLER index) → loop i: 0 UP TO n

Starting index — ask ONE question: is this index's value already hardcoded, or does the recurrence still need to compute it?

Already hardcoded outside the loop (a true base case, e.g. dp[n] = 0)
  → loop EXCLUDES it, starts one step further in

Not hardcoded — computed BY the recurrence using a virtual sentinel
before/after the array (e.g. treating dp[-1] as 0)
  → loop INCLUDES it, starts right there

📐 Example — hardcoded base (excluded from loop):

dp[n] = 0;                          // base case, set once, outside
for (i = n - 1; i >= 0; i--) { ... }  // excludes n

📐 Example — computed via sentinel (included in loop):

// dp[i] built from dp[i-1], "nothing before index 0" = sentinel 0
for (i = 0; i <= n; i++) {
    dp[i] = (i === 0 ? 0 : dp[i - 1]) + something;
}
📌 Direction = which side the recurrence reads from. Starting index = the first slot NOT already hardcoded before the loop runs. Don't memorize "0 to n" or "n-1 to 0" as a rule — re-derive both from the recurrence every time.

3 · 🎯 Skip/Take vs "Committed Rule" DP — When Skip/Take Breaks

🎯 Skip/Take works when "take or skip" depends on ONE thing: comparing to the LAST picked element.

✅ LIS: "is nums[i] > nums[prev]?" — one comparison, one reference point. Skip/Take works fine.

🚨 Some problems need a rule the CHAIN ALREADY COMMITTED TO — not just the last value:

📐 1027 Longest Arithmetic Subsequence: "does nums[i] continue the SAME DIFFERENCE this chain already has?" — but a chain only HAS a difference once it's got 2+ elements. Skip/Take (state = just prev) can't express this.

🧠 Simple test "To decide take-or-skip at i, do I need just the LAST element, or a RULE the chain already locked in?"
  • Just last element → 🟢 Skip/Take, state = (i, prev)
  • A committed rule (difference, ratio, count) → 🔴 state = (i, thatRule), found via PAIRWISE scan, not skip/take

📌 Problems in this "committed rule" family:

  • 1027 Longest Arithmetic Subsequence — rule = the common difference
  • 873 Length of Longest Fibonacci Subsequence — rule = the last TWO numbers, state = (j, i)

Not in this family: 673 Number of LIS and 368 Largest Divisible Subset only compare with the last element, so they are plain LIS shape (#4).

🟢 LIS pseudocode (skip/take works — state = just prev):

dfs(i, prevIdx):
  if i === n: return 0
  skip = dfs(i+1, prevIdx)
  take = 0
  if prevIdx === -1 or nums[i] > nums[prevIdx]:
    take = 1 + dfs(i+1, i)
  return max(skip, take)

🔴 1027 Longest Arithmetic Subsequence — recursive framing (state = committed rule, "ending at i"):

// dfs(i, diff) -> longest arithmetic subsequence ENDING AT index i, using common difference diff
memo = map, keyed by (i, diff)

dfs(i, diff):
  if memo has (i, diff): return memo[(i, diff)]
  best = 1   // just this element alone, base length
  for j in 0..i:
    if nums[i] - nums[j] === diff:
      best = max(best, 1 + dfs(j, diff))
  memo[(i, diff)] = best
  return best

answer = max over all i, all diff = nums[i]-nums[j] for j<i, of dfs(i, diff)
🔑 "Ending at i" is the STANDARD framing for this whole family — anchor the state at the LAST index, then ask "for every earlier j, if I extend THAT chain (ending at j, same diff) by adding nums[i], what do I get?" State = (i, diff), not (i, prevIndex) — the DIFFERENCE itself is what got "committed" and must be carried forward.

🔴 1027 as tabulation

🔑 dp[i][diff] = length of the longest arithmetic chain ending at i with common difference diff. Diff can be negative (-500..500), so offset it to use as an array index.
Full LC 1027 code 
function longestArithSeqLength(nums: number[]): number {
    const n = nums.length;

    // diff range -500 to 500
    const OFFSET = 500;

    const dp = Array.from({length: n}, () => Array(1001).fill(1));

    let ans = 1;

    for(let i = 0; i < n; i++) {
        for(let j = 0; j < i; j++) {
            const diff = nums[i] - nums[j];
            const key = diff + OFFSET;

            dp[i][key] = Math.max(dp[i][key], 1 + dp[j][key]);
            ans = Math.max(ans, dp[i][key]);
        }
    }

    return ans;
}

📐 Why dp[j][key] (same key): nums[i] - nums[j] = diff extends the chain ending at j with that SAME diff, so read dp[j] at the same key. It is the tabulated dfs(i, diff) above.

📌 If the extension rule only needs the LAST value, it's skip/take. If it needs a relationship the chain already locked in, the state must CARRY that relationship — found by scanning PAIRS, not by skip/take.

4 · 🔗 LIS-Family: Natural Recursion ≠ Standard DP (Different States, Not a Compression)

🎯 For LIS-shaped problems, the recursion you'd naturally write and the DP everyone actually uses are TWO DIFFERENT state definitions — the DP is NOT a rolling-array compression of the recursion's memo table.

🔴 Natural recursion dfs(i, prevIdx), take/skip:
dfs(i, prevIdx):
  skip = dfs(i+1, prevIdx)
  take = 0
  if condition(nums[i], nums[prevIdx]):
    take = 1 + dfs(i+1, i)
  return max(skip, take)

→ O(2ⁿ) raw. Memoized: state = (i, prevIdx) → O(n²) states × O(1) work = O(n²) time, O(n²) space.

✅ Standard/cleaner DP dp[i] = "best chain ENDING AT i", found by scanning j < i:
for i in 0..n:
  for j in 0..i:
    if condition(nums[i], nums[j]) and dp[j]+1 > dp[i]:
      dp[i] = dp[j] + 1

→ Also O(n²), but with O(n) space — a smaller, DIFFERENT state (dp[i] alone, no prevIdx dimension).

Problems in this family: LC 300 Longest Increasing Subsequence, LC 368 Largest Divisible Subset, LC 673 Number of LIS. LC 1027 also ends at i, but needs the diff in its state (#3).

🔗 LC 368 Largest Divisible Subset — LIS with %

Sort first. Then nums[i] % nums[j] === 0 for j < i is enough, because divisibility carries along the sorted order. length[i] = longest chain ending at i, and prevIdx[] lets you walk back to rebuild the subset itself.

Full LC 368 code 
function largestDivisibleSubset(nums: number[]): number[] {
    const n = nums.length;
    nums.sort((a, b) => a - b);

    const length = Array(n).fill(1);
    const prevIdx = Array(n).fill(-1);

    let maxLen = 1;
    let lastChosenIdx = 0;

    for (let i = 0; i < n; i++) {
        for (let j = 0; j < i; j++) {
            if (nums[i] % nums[j] !== 0) continue;

            if (length[j] + 1 > length[i]) {
                length[i] = length[j] + 1;
                prevIdx[i] = j;
            }

            if (length[i] > maxLen) {
                maxLen = length[i];
                lastChosenIdx = i;
            }
        }
    }

    const res: number[] = [];
    while (lastChosenIdx !== -1) {
        res.push(nums[lastChosenIdx]);
        lastChosenIdx = prevIdx[lastChosenIdx];
    }

    return res;
}
🔑 The recursion you'd write first ((i, prevIdx) take/skip) and the DP everyone actually codes (dp[i] ending-at-i, scan j<i) are different STATE DEFINITIONS that coincidentally match on TC — not one compressed from the other. Need the items, not just the count? Keep prevIdx[] and walk back.

🔑 Why subtract 1 cutting a string into k palindrome pieces needs exactly k-1 cuts (fence-post logic — 3 pieces, 2 gaps between them).
"aab" → pieces: ["aa","b"] → 2 pieces → 1 cut

function dfs(start: number): number {

6 · 🗡️ Dungeon Game — Need Here = Need Ahead − This Cell (at least 1)

🎯 dfs(r, c) = the minimum HP needed walking INTO this cell. Leap of faith: trust dfs to give the need for the rest of the trip.

// past the destination → 1 (just survive). Off the grid → Infinity
const neededAhead = Math.min(dfs(r + 1, c), dfs(r, c + 1))
return Math.max(1, neededAhead - dungeon[r][c])

➖ Why subtract: damage -2 → need goes UP by 2. Heal +8 → need goes DOWN by 8. One formula covers both.

🛡️ Why max(1, …): HP can never be 0 or below, even if a big heal "covers" everything ahead.

📌 Need here = need ahead − this cell, never below 1. After the last cell, need ahead = 1.

7 · 🎲 Stone Game Family — Each Variant Has Its OWN Shape, Don't Force-Fit

🚨 Don't carry one Stone Game's shape over to another by default — the move rule decides the recursion shape.

🅰️ Stone Game I — front/back pick, NO for-loop, Math.min-the-opponent

Every move removes exactly ONE pile from either END (i or j) → state stays a clean interval [i,j]. Two explicit choices only — no loop needed. Opponent (next player) wants to MINIMIZE what's left for you:

function dfs(i: number, j: number): number {
    // base case
    if(i > j) return 0;

    const pickStart = piles[i] + Math.min(dfs(i + 2, j), dfs(i + 1, j - 1));
    const pickEnd = piles[j] + Math.min(dfs(i, j - 2), dfs(i + 1, j - 1));

    return Math.max(pickStart, pickEnd);
}

🅱️ Stone Game II — variable move size, for-loop + suffix sum

Move size X isn't fixed (1..2M) → single advancing pointer i, no "other end." For-loop tries every X, subtracts the opponent's best from here, takes the max:

function dfs(idx: number, m: number): number {
    // base case
    if(idx >= n) return 0;
    if(idx + 2 * m >= n) return suffix[idx]; // must be suffix[idx], NOT suffix[0] — remaining sum, not total sum

    let best = Number.MIN_SAFE_INTEGER;
    for(let x = 1; x <= 2 * m; x++) {
        const taken = suffix[idx] - suffix[idx + x];
        const oppoTake = dfs(idx + x, Math.max(m, x));
        best = Math.max(best, taken - oppoTake);
    }

    return best;
}

🅲 Stone Game VII — front/back pick like SG1, but needs PREFIX SUM for scoring

Like SG1, picks from either end — but the SCORE for a move isn't piles[i]/piles[j] directly, it's the SUM of whatever stones remain after removing that pile. Needs a prefix-sum array for O(1) range-sum lookup. Shape follows SG1 (2 explicit choices, no loop) since it's still a fixed-one-pile-per-move front/back game:

function dfs(i: number, j: number): number {
    // base case
    if(i >= j) return 0;

    const pickFront = (prefix[j + 1] - prefix[i + 1]) - dfs(i + 1, j);
    const pickBack = (prefix[j] - prefix[i]) - dfs(i, j - 1);

    return Math.max(pickFront, pickBack);
}
🎯 When prefix/suffix? Only when a move's value is a RANGE. SG2 takes a chunk, SG7 scores the stretch that's left. SG1 takes one pile, so there is nothing to sum.
📌 The MOVE RULE decides the shape — copy the move rule, not the code.

1 · 🎯 Binary Search — Master Summary

🔍 Normal (find exact element)

🔑 low/high are ARRAY INDICES — you navigate by index, but compare the ELEMENT'S VALUE at that position.
low = 0, high = n-1
while (low <= high) {

📐 Boundary search (find a threshold, not an exact element)

🎯 THE ONE THING TO THINK ABOUT: the answer might not exist, so the range gets ONE extra slot for "none". It goes on the side you move AWAY from:

  • ⬅️ Searching LEFT (first one that works) → extra slot on the right: high = n (or max value + 1)
  • ➡️ Searching RIGHT (last one that works) → extra slot on the left: low = -1 (or min value − 1)
🔑 Same rule for value spaces and array indices. Normal search uses n-1 because the answer MUST exist inside. Land on the extra slot = nothing works.

Style A, searching LEFT (shrink toward smaller):

low = 0, high = n
while (low < high) {
    mid = (low+high) >> 1        // round DOWN
    if (condition(mid)) high = mid
    else low = mid + 1
}
return low   // low === high === the answer

Style A, searching RIGHT (grow toward bigger):

low = -1, high = n - 1          // -1 = "nothing works"
while (low < high) {
    mid = (low+high+1) >> 1      // round UP — REQUIRED
    if (condition(mid)) low = mid
    else high = mid - 1
}
return low   // low === high === the answer

🧩 LIS tails lower bound is just Style A LEFT with condition = arr[mid] >= target. lo is where to insert or replace.

📐 Concrete worked example — Russian Doll Envelopes (354), sort by width ASC / height DESC on ties, then LIS on heights:

function maxEnvelopes(env: number[][]): number {
    env.sort((a, b) => {
        if (a[0] === b[0]) return b[1] - a[1];
        return a[0] - b[0];
    });

    const hei = env.map(a => a[1]);
    const tails: number[] = [];

    for (const h of hei) {
        let lo = 0, hi = tails.length;
        while (lo < hi) {
            const mid = (lo + hi) >> 1;
            if (tails[mid] >= h) hi = mid;
            else lo = mid + 1;
        }
        if (lo === tails.length) tails.push(h);
        else tails[lo] = h;
    }

    return tails.length;
}

Style B (kept for reference):

low = 0, high = n - 1, ans = -1   // ans stays -1 if nothing works
while (low <= high) {
    mid = (low+high) >> 1
    if (condition(mid)) { ans = mid; high = mid - 1 }  // searching LEFT
    else low = mid + 1
}
return ans
🎯 Recommendation Default to Style A for all boundary search: no extra ans variable, low/high meet at the answer. Know Style B only to read other people's solutions.

🧠 Arrays & Strings — Must Remember

  • 🗺️ Range sum i..j = p[j+1] − p[i], the +1 goes on j (#1)
  • 🪟 All positive → sliding window · any negative → prefix sum + map (#2)
  • 🧮 exactly(k) = atMost(k) − atMost(k−1) (#3)
  • 🔄 Negative step on a circle → ((x % n) + n) % n (#4)
  • 🔗 One-to-one → check both directions (#5)
  • ✂️ k pieces = k − 1 cuts, each cut leaves room for the rest (#6)

1 · 🗺️ Prefix / Suffix — Range Sum in O(1), the +1 Goes on j

index:      0    1    2    3    4    5
piles:    [ 2 ][ 7 ][ 9 ][ 4 ][ 4 ]

suffix:   [26 ][24 ][17 ][ 8 ][ 4 ][ 0 ]
                                    ↑ sentinel (nothing after index 4)

prefix:   [ 0 ][ 2 ][ 9 ][18 ][22 ][26 ]
            ↑ sentinel (nothing before index 0)

🎯 Suffix sentinel sits at the END. Prefix sentinel sits at the START. Both mean the same thing: "empty range → 0."

suffix[i] INCLUDES piles[i]. prefix[i] EXCLUDES it (sum of everything before i).

➕ Sum of i..j (inclusive): the +1 always goes on j.

prefix[j + 1] - prefix[i]   // 1..3 → 22 - 2 = 20 (7 + 9 + 4)
suffix[i] - suffix[j + 1]   // 1..3 → 24 - 4 = 20

🔁 Same trick, other interview shapes:

  • 🎯 Subarray sum = k (LC 560): count seen[prefix - k]. Start with seen = {0: 1}, that's the sentinel (empty prefix).
  • ⊕ Range XOR: px[j + 1] ^ px[i], same shape as sum.
  • 🔲 2D range sum (LC 304): P[r2+1][c2+1] - P[r1][c2+1] - P[r2+1][c1] + P[r1][c1] (add back the corner you subtracted twice).
  • 📈 Range ADD (difference array): diff[i] += v, diff[j + 1] -= v, then prefix-sum it. The +1 lands on j again.
  • ✖️ Product except self (LC 238): left[i] * right[i], both EXCLUDE i.
📌 Size n+1, sentinel 0 = empty range. For i..j the +1 always goes on j. Prefix: p[j+1] - p[i]. Suffix: s[i] - s[j+1].

2 · 🪟 Subarray Sum: Sliding Window or Prefix Sum + Map?

NumbersUse
➕ all positive🪟 sliding window
➖ all negative🔄 flip signs (×−1), then window
➕➖ mixed🗃️ prefix sum + map (#1, LC 560)

🔑 Why: a window needs one direction. Adding an element must always push the sum the same way, so you know which pointer to move. Mixed signs break that.

💥 [5, -3, 1], target 3: the window drops 5 as "too big" before -3 arrives, and never finds the whole array.

⚠️ Zeros: "sum ≥ target, min length" still works with a window. Counting exact sums with zeros (LC 930) needs atMost(k) − atMost(k−1) or prefix sum + map.
📌 All positive → window. Any negatives → prefix sum + map.

3 · 🧮 Count Subarrays: Turn Everything Into atMost()

atMost(k)   // shrink while count > k, then res += right - left + 1
atLeast(k) = total - atMost(k - 1)   // total = n * (n + 1) / 2
exactly(k) = atMost(k) - atMost(k - 1)

🔑 Why: every subarray is ≥ k or ≤ k − 1, never both, so all = atLeast(k) + atMost(k − 1).

🎓 5 students: 3 scored ≥ 60, 2 scored ≤ 59 → atLeast(60) = 5 − 2 = 3.

⚠️ atMost(-1) must return 0 (matters when k = 0). Works only when the count can't drop as the window grows (odd numbers, distinct values). Negative numbers → prefix sum + map (#2).
📌 Counting "exactly" or "at least"? Write atMost once and subtract.

4 · 🔄 Circular Index — Wrap Any Jump With + n

🎯 Cue: a circular array where you jump by a value that can be negative (LC 457 Circular Array Loop, LC 3379 Transformed Array).

next = ((i + step) % n + n) % n;   // always 0…n-1
  • ⚠️ Why: JS % keeps the sign of the left side, so (0 - 1) % 5 is -1, an invalid index.
  • 🧠 % n brings it into -(n-1)…n-1, + n makes it non-negative, the last % n folds it back under n.
📌 Step can be negative? Use ((x % n) + n) % n, never plain x % n. JS detail: JS #11.

5 · 🔗 One-to-One Mapping — Check Both Directions

🎯 Cue: "each X maps to exactly one Y, and no two X share a Y". LC 205 Isomorphic Strings, LC 290 Word Pattern.

  • 🔁 Keep X→Y consistent and Y→X consistent.
  • 🧰 Two maps, or one map plus a Set of used values.
  • ⚠️ One direction is not enough: "ab" → "aa" passes X→Y but fails Y→X.
📌 One-to-one means check both directions.

6 · ✂️ Split Into k Pieces — k−1 Cuts, and Each Cut Leaves Room for the Pieces After It

🎯 A string of n characters has n − 1 gaps. k pieces = pick k − 1 gaps (3 pieces → 2 cuts 🔪🔪). This is the same fence-post idea as DP #5, here used to write the loop bounds.

🔪 Slice (cut positions)📦 Array (inclusive end)
Pieces[0,i) [i,j) [j,n)[0..i] [i+1..j] [j+1..n-1]
i1 to n − 20 to n − 3
ji + 1 to n − 1i + 1 to n − 2
for (let i = 1; i <= n - 2; i++)          // slice cuts
    for (let j = i + 1; j <= n - 1; j++) {}

for (let i = 0; i < n - 2; i++)           // array ends
    for (let j = i + 1; j < n - 1; j++) {}

🔒 Why the limits stop early: every piece after a cut needs at least 1 character. The 3rd piece needs 1 → j stops 1 early. The 2nd and 3rd need 2 → i stops 2 early. The array version is just the slice version shifted by 1.

🚨 Array version: j starts at i + 1 (not 0) and stops at n − 2 (not n − 1). Running j up to n and then writing if (j === n) break gives the same splits — that guard IS the "3rd piece can't be empty" rule — but putting the limit in the loop bounds is cleaner (LC 306 Additive Number).
📌 k pieces = k − 1 cuts. Each cut leaves room for the pieces after it. Slice → cuts in 1..n−1. Array → piece ends in 0..n−2. Number of splits = C(n−1, k−1) (n = 5, 3 pieces → 6).

🧠 JS Gotchas — Must Remember

  • 🚨 Out of bounds → silent undefined, guard with ?? 0 (#1)
  • ⚠️ || / && can skip a second call: call side-effect functions first (#2)

1 · 🚨 JS Never Throws on Out-of-Bounds Array Access

🎯 arr[100] (too big) or arr[-1] (negative) → both silently return undefined. NO crash, NO error.

🚨 Java throws on both. Python throws on too big, but arr[-1] is the last element there. JS does neither, so the bug stays hidden.

💥 One case does crash: a missing ROW. dp[n] is undefined, so dp[n][j] throws TypeError: Cannot read properties of undefined.

🔑 Why this is dangerous undefined silently flows into math. Math.min(5, undefined) = NaN. Once NaN appears, it POISONS every calculation built on top of it — but nothing crashes, so the bug hides until the FINAL wrong answer shows up.

📐 Where I hit this: Stone Game DP — dp[i+1][j-1] when j=0 reads dp[1][-1] → undefined → Math.min(0, undefined) = NaN → cascaded corruption through the whole table.

✅ The fix: ?? 0 (or another sensible default) right at the access point:

dp[i+1][j-1] ?? 0   // undefined → 0, before it reaches Math.min/arithmetic
📌 JS out-of-bounds = silent undefined, not a crash. Anywhere an index MIGHT go negative or past the end, guard with ?? default right at the read, or the bug hides until a wrong final answer.

2 · 🚨 || / && Short-Circuit SILENTLY Skips a Second Call With Side Effects

🎯 A || B and A && B don't always evaluate both sides — JS stops early the moment the result is already decided.

A || B → if A is truthy, B is NEVER CALLED (result already true)
A && B → if A is falsy,  B is NEVER CALLED (result already false)
🚨 This is invisible and dangerous when B is a function call with its OWN side effect (mutates state, unions a DSU, pushes to an array) — not just a pure boolean check.

📐 Where it bit — LC 1579 (Remove Max Edges, dual Union-Find for Alice+Bob):

if(alice.union(u, v) || bob.union(u, v)) edgesUsed++;   // ❌

If alice.union(u, v) returns true (union succeeded), bob.union(u, v) never runs at all — short-circuited. For a "shared" edge meant to help BOTH graphs, Bob's DSU silently misses the merge whenever Alice's happens to succeed first. No error, no crash — just a wrong final answer.

✅ Fix — call both FIRST, combine the booleans AFTER:

const usedByAlice = alice.union(u, v);
const usedByBob = bob.union(u, v);
if (usedByAlice || usedByBob) edgesUsed++;
🔑 The moment a ||/&& operand is a function call that MUTATES something (not just reads a value), short-circuiting becomes a correctness bug — call every side-effecting function separately first, THEN combine the results in a boolean expression.
