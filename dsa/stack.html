🥞 Stack & Monotonic Stack

A learning sheet — a stack remembers what's unresolved and settles it in reverse. The monotonic variant turns O(n²) "nearest larger/smaller" scans into one pass.

🧠 1 · How to think (and invent it)

The plain idea: a stack is "things I've seen but can't finish yet," resolved last-in-first-out. Openers wait for closers; a sub-expression waits until its ]; the call stack waits for each return.

The powerful idea — the monotonic stack: keep the stack sorted (always increasing, or always decreasing). When a newcomer would break that order, pop the elements it dominates and resolve each one against the newcomer. Because every element is pushed once and popped once, an apparently nested loop is actually O(n).

Mental checklist (monotonic) (1) increasing or decreasing stack? (2) pop on < or <= (how to treat ties)? (3) store indices (if you need distance/width) or values? (4) what do you compute at the moment of popping — that pop is when an element's answer becomes known.

Watch it get invented — Daily Temperatures

For each day, how many days until a warmer one? temps = [73,74,75,71,69,72,76,73].

  1. Start brute. For each i, scan right for the first warmer day → O(n²), re-scanning the same cold stretch over and over.
  2. Spot the waste. Keep a stack of days still waiting for a warmer one — naturally in decreasing temperature. A warm newcomer resolves all the colder days on top at once, and a day is resolved exactly once.
  3. The leap. Decreasing stack of indices. While temps[top] < temps[i]: pop, set ans[top] = i − top. Then push i.
  4. Payoff. Each index pushed once, popped once ⇒ O(n).

275pop 1 → ans[1]=1[2]
572pop 4 (ans=1), pop 3 (ans=2)[2, 5]

Answer: [1,1,4,2,1,1,0,0]. Days never resolved (no warmer ahead) keep their default 0.

🧩 4 · The five core patterns

§4.3–4.5 are the monotonic family — same engine (push-once/pop-once), different "what you compute on pop." Each pattern: a one-liner, a 🔑 invariant, a template, and a 🎤 interview lens.

4.1 · Matching & nesting

“Push what's open; a closer must match the most recent opener.”

Setup: the only thing that can close an opener is the nearest unclosed one — pure LIFO.

🔑 Invariant — why it's safe The stack always holds the still-open brackets in the exact order they must close. So the next valid closer is uniquely determined by the top — a single comparison decides validity.
function isValid(s: string): boolean {
  const stack: string[] = [];
  const match: Record<string, string> = { ')': '(', ']': '[', '}': '{' };
  for (const c of s) {
    if (c in match) { if (stack.pop() !== match[c]) return false; }  // closer: must match top
    else stack.push(c);                                             // opener: wait
  }
  return stack.length === 0;   // nothing left unclosed
}
🎤 Interview lens Probed: the two empty-stack checks (pop on empty = bad closer; non-empty at end = unclosed). · Escalation: valid parens → "min add/remove to make valid" → "longest valid parentheses" (stack of indices, or DP).

4.2 · Parse / evaluate — a stack of context

“Hit a sub-part — stash what you were doing; finish it; pop and resume.”

Setup: when you descend into a bracketed/nested piece, push the surrounding state; when it ends, pop and splice the result back.

🔑 Invariant — why it's safe At any moment the stack holds, from bottom to top, the unfinished work of each enclosing level. Popping restores exactly the parent's state, so nesting of any depth resolves correctly.
// Decode String:  "3[a2[c]]" -> "accaccacc"
function decodeString(s: string): string {
  const numStack: number[] = [], strStack: string[] = [];
  let cur = '', num = 0;
  for (const c of s) {
    if (c >= '0' && c <= '9') num = num * 10 + (+c);           // multi-digit
    else if (c === '[') { numStack.push(num); strStack.push(cur); num = 0; cur = ''; } // descend
    else if (c === ']') { const k = numStack.pop()!; cur = strStack.pop()! + cur.repeat(k); } // resume
    else cur += c;
  }
  return cur;
}
🎤 Interview lens Probed: multi-digit numbers and arbitrary nesting depth. · Escalation: decode string → "Basic Calculator I/II/III" (operators + precedence with a stack) → evaluate RPN.

4.3 · Monotonic stack — nearest greater / smaller

“A newcomer resolves everyone it dominates, all at once.”

Setup: maintain a stack of indices whose answers aren't known yet, kept monotonic. The newcomer pops (and answers) every waiting element it beats.

🔑 Invariant — why it's safe The stack holds exactly the elements whose "next greater" is still unknown, in strictly decreasing value order. So the first element a newcomer fails to beat blocks everything beneath it — no need to look deeper. Each index is pushed and popped once ⇒ O(n).
// Next Greater Element — res[i] = next value to the right greater than a[i], else -1
function nextGreater(a: number[]): number[] {
  const res = new Array(a.length).fill(-1);
  const stack: number[] = [];                 // indices; a[stack] strictly decreasing
  for (let i = 0; i < a.length; i++) {
    while (stack.length && a[stack[stack.length - 1]] < a[i]) {
      res[stack.pop()!] = a[i];                // a[i] is the answer for the popped index
    }
    stack.push(i);
  }
  return res;                                   // anything left has no greater → stays -1
}
🎤 Interview lens Probed: increasing vs decreasing, < vs <= (ties), indices vs values, and the amortized O(n). · Escalation: next greater → Daily Temperatures → "Next Greater Element II" (circular: iterate 2n with i % n) → online Stock Span.

4.4 · Monotonic stack — spans & areas

“When a bar pops, that's the instant its full width is known.”

Setup: an increasing stack of indices. When a shorter bar arrives, each taller bar it pops can't extend further right — so compute its rectangle at the pop: width = (current index) − (index below it on the stack) − 1.

🔑 Invariant — why it's safe The stack holds bars in increasing height; the bar below any bar is its nearest shorter on the left, and the bar that pops it is its nearest shorter on the right. Those two bounds give the exact maximal width for that height — computed precisely once, at the pop.
// Largest Rectangle in Histogram
function largestRectangle(h: number[]): number {
  const stack: number[] = [];          // indices; heights increasing
  let best = 0;
  for (let i = 0; i <= h.length; i++) {
    const cur = i === h.length ? 0 : h[i];          // sentinel 0 flushes the stack
    while (stack.length && h[stack[stack.length - 1]] >= cur) {
      const height = h[stack.pop()!];
      const left = stack.length ? stack[stack.length - 1] : -1;  // nearest shorter on left
      best = Math.max(best, height * (i - left - 1));            // width spans (left, i)
    }
    stack.push(i);
  }
  return best;
}
🎤 Interview lens Probed: the width formula i − left − 1 and the trailing sentinel that flushes. · Escalation: histogram → "Maximal Rectangle" in a 0/1 matrix (run this per row) → "Trapping Rain Water" (bounded by nearest taller on both sides).

4.5 · Monotonic stack — greedy lexicographic build

“Build the result greedily; pop a worse predecessor while you still can.”

Setup: construct an output by pushing characters; before pushing, pop earlier characters that are "worse" than the newcomer if your removal budget allows. The stack is the answer-in-progress.

🔑 Invariant — why it's safe The stack is always the lexicographically best prefix achievable from what's been read, given how many removals you've spent. Popping a larger digit before a smaller newcomer strictly improves the prefix and can never be regretted.
// Remove K Digits — smallest number after deleting k digits
function removeKdigits(num: string, k: number): string {
  const stack: string[] = [];
  for (const d of num) {
    while (k > 0 && stack.length && stack[stack.length - 1] > d) { stack.pop(); k--; } // drop bigger predecessors
    stack.push(d);
  }
  while (k-- > 0) stack.pop();                       // leftover budget → trim the tail (digits ascending)
  return stack.join('').replace(/^0+/, '') || '0';  // strip leading zeros
}
🎤 Interview lens Probed: the leftover-k tail trim, and leading zeros. · Escalation: remove k digits → "Remove Duplicate Letters / Smallest Subsequence" (pop only if the char reappears later, and isn't already in the stack) → "Create Maximum Number."

⏱️ 5 · Complexity

PatternTimeSpaceNote
Matching / ParseO(n)O(n)stack depth ≤ nesting depth
Monotonic (next / area / greedy)O(n)O(n)each element pushed once, popped once
The amortized argument The inner while can pop many elements in one step, which looks like O(n²) — but across the whole run there are exactly n pushes, so at most n pops total. Total work is O(n). This "push-once, pop-once" line is the proof every monotonic-stack answer must state.

➕ Three more stack shapes — Visible People (1944) · Exclusive Time (636) · Max Chunks II (768)
Same monotonic-stack machinery, three new roles: count while you pop (1944), the stack is the call stack (636), and each stack element summarises one group (768).
// 1944 Number of Visible People in a Queue — scan RIGHT→LEFT, decreasing stack
function canSeePersonsCount(h: number[]): number[] {
  const res: number[] = new Array(h.length).fill(0), st: number[] = [];
  for (let i = h.length - 1; i >= 0; i--) {
    while (st.length && h[st[st.length - 1]] < h[i]) { st.pop(); res[i]++; }   // every shorter person is visible
    if (st.length) res[i]++;                                                    // plus the first person >= me
    st.push(i);
  }
  return res;
}

// 636 Exclusive Time of Functions — simulate the call stack
function exclusiveTime(n: number, logs: string[]): number[] {
  const res: number[] = new Array(n).fill(0), st: number[] = [];
  let prev = 0;
  for (const log of logs) {
    const [id, type, t] = log.split(':'); const ts = +t;
    if (type === 'start') {
      if (st.length) res[st[st.length - 1]] += ts - prev;   // caller runs until the callee starts
      st.push(+id); prev = ts;
    } else {
      res[st.pop()!] += ts - prev + 1;                       // end timestamp is INCLUSIVE
      prev = ts + 1;
    }
  }
  return res;
}

// 768 Max Chunks To Make Sorted II — each stack element = the MAX of one chunk
function maxChunksToSorted(arr: number[]): number {
  const st: number[] = [];
  for (const x of arr) {
    if (!st.length || x >= st[st.length - 1]) { st.push(x); continue; }   // >= keeps duplicates in separate chunks
    const cur = st[st.length - 1];                                         // the merged chunk's max
    while (st.length && st[st.length - 1] > x) st.pop();                   // absorb every chunk whose max exceeds x
    st.push(cur);
  }
  return st.length;
}
⚠️ Traps 1944: pop on strictly shorter; the trailing +1 counts the first person ≥ you. 636: the +1 on end and prev = ts + 1. 768: push with >=; push back the old top (cur), not x.
