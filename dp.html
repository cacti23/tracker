🧠 SECTION 1: THE 30-SECOND DECISION FRAMEWORK

When a DP problem lands, ask in this order:

┌─────────────────────────────────────────┐
│ STEP 1: CAN IT BE SOLVED RECURSIVELY?   │
├─────────────────────────────────────────┤
│ □ Define a recursive function dfs(...)  │
│ □ Identify base case(s)                 │
│ □ Draw recursion tree (small example)   │
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│ STEP 2: OVERLAPPING SUBPROBLEMS?        │
├─────────────────────────────────────────┤
│ □ Highlight repeated nodes in tree      │
│ □ If none exist → backtracking (no DP)  │
│ □ If yes → move to memoization          │
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│ STEP 3: OPTIMAL SUBSTRUCTURE?           │
├─────────────────────────────────────────┤
│ □ Does optimal solution to larger       │
│   problem rely on optimal solutions to  │
│   subproblems?                          │
│ □ If yes → DP is applicable             │
│ □ If no → greedy or other approach      │
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│ STEP 4: CHOOSE APPROACH                 │
├─────────────────────────────────────────┤
│ Memoization (top-down): Recursive,      │
│   easier to code, memory for stack      │
│ Tabulation (bottom-up): Iterative,      │
│   space optimization, 1D→2D rolling     │
└─────────────────────────────────────────┘

📚 SECTION 3: CORE DP CONCEPTS

3.1 The Three Pillars

PILLAR 1: OPTIMAL SUBSTRUCTURE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Definition: Solution to problem P relies on optimal solutions to subproblems P1, P2, ...
Example (Fibonacci):
  fib(5) = fib(4) + fib(3)
  fib(5)'s optimal solution uses fib(4) and fib(3) optimally.
  If either were suboptimal, fib(5) would be suboptimal.

Test: Can you write: problem(input) = combine(problem(smaller_input))?
      If YES → likely has optimal substructure.

PILLAR 2: OVERLAPPING SUBPROBLEMS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Definition: Same subproblem is solved multiple times in recursive tree.
Example (Fibonacci):
  fib(5)
    ├─ fib(4)
    │  ├─ fib(3)       ← computed
    │  └─ fib(2)
    └─ fib(3)         ← RECOMPUTED (overlapping!)

Without memoization: O(2^n) due to overlaps
With memoization: O(n) — compute each state once

PILLAR 3: MEMOIZATION = TRADE TIME FOR SPACE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Without DP: Time O(2^n), Space O(n) [recursion stack only]
With DP:    Time O(n), Space O(n) [cache + stack]

Tradeoff: Pay O(n) space to save O(2^n - n) time.
          Almost always worth it.

3.2 Backtracking vs DP: Crucial Distinction

BACKTRACKING ALONE (Pure Exploration):
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Use When: Each state visited once (no repeated subproblems)
Examples:
  □ LC 46 (Permutations) — explore all n! orderings, no repeats
  □ LC 51 (N-Queens) — each board config unique
  □ LC 22 (Generate Parentheses) — each valid combo once
  □ LC 39 (Combination Sum) — path to target unique
Pattern: Recursion tree is a TREE (no repeated nodes)
Result: Can use backtracking alone, no memoization needed

BACKTRACKING + MEMOIZATION = DP:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Use When: Same subproblem solved multiple times
Examples:
  □ LC 494 (Target Sum) — reach(index, current_sum) called repeatedly
  □ LC 1049 (Last Stone II) — sameState visited via different paths
  □ LC 377 (Combination Sum IV) — count(remaining) solved many times
Pattern: Recursion tree has REPEATED nodes
Signal: If backtracking + memo → memoization (store result, skip recomputation)

HOW TO RECOGNIZE:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Try writing recursive brute force. Run on small example. Does it TLE?
  - If TLE on n=20 but should pass → overlapping subproblems → add memo
  - If passes on n=20 cleanly → no overlaps → pure backtracking OK

CONCRETE EXAMPLES:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
LC 494 (Target Sum):
  dfs(index, sum) is called repeatedly:
    index=2, sum=0  ← appears via multiple paths in tree
  → overlapping subproblems
  → add memo: memo[index][sum] = ways to make sum starting at index

LC 46 (Permutations):
  dfs(used_mask) is called once per mask (2^n total states)
    No overlap: each [a,b,c] appears once
  → no memoization needed, backtracking sufficient

// TYPE DEFINITIONS FOR MEMOIZATION STORAGE
type Memo1D = (number | undefined)[];
type Memo2D = (number | undefined)[][];
type MemoMap = Map<string, number>;

// PATTERN 1: 1D Array (fastest, use for fixed state)
const memo1D: Memo1D = new Array(n).fill(undefined);
memo1D[i] = value; // O(1) access

// PATTERN 2: 2D Array (for 2-parameter state)
const memo2D: Memo2D = Array.from({ length: n }, () => new Array(m).fill(undefined));
memo2D[i][j] = value;

// PATTERN 3: Map (for complex state, string-encoded)
const memoMap: MemoMap = new Map();
const key = `${i},${j}`; // ALWAYS use separator!
memoMap.set(key, value);

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
// GOTCHA 1: undefined vs -1 as "not computed" sentinel
// ❌ WRONG: Using 0 as sentinel

if (!memo[i]) return dfs(i); // FAILS if result is 0!

// ✅ CORRECT: Use undefined or -1
const memo = new Array(n).fill(undefined);
if (memo[i] === undefined) return dfs(i);
// OR
const memo = new Array(n).fill(-1);
if (memo[i] === -1) return dfs(i);

// GOTCHA 2: Map key collisions (no separator)
// ❌ WRONG:

const key = `${i},${j}`; // Always use non-numeric separator
memoMap.set(key, value);

// ❌ WRONG:

const grid = Array.from({ length: n }, () => new Array(m).fill(0));

🎯 SECTION 5: MEMOIZATION vs TABULATION DECISION TREE

MEMOIZATION (TOP-DOWN) — START HERE WHEN UNCERTAIN
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Use When:
  □ Solution is naturally recursive (problem says "or")
  □ Many states unreachable (sparse subproblems)
  □ Want cleaner code that mirrors problem statement
  □ Recursion depth ≤ 10K (no stack overflow)
  □ Only need one answer (not all dp[] values)

Pros:
  ✓ Code mirrors mathematical definition
  ✓ Only computes reachable states (no waste)
  ✓ Easy to debug (familiar recursion)
  ✓ Usually faster constant factors

Cons:
  ✗ Stack overflow on deep recursion
  ✗ Hard to optimize space (can't use rolling arrays)
  ✗ Harder to trace execution (recursive calls hidden)

Example (LC 70 Climbing Stairs):
  function climb(n: number): number {
    const memo: number[] = new Array(n + 1).fill(-1);
    function dfs(remaining: number): number {
      if (remaining === 0) return 1;
      if (remaining < 0) return 0;
      if (memo[remaining] !== -1) return memo[remaining];
      return memo[remaining] = dfs(remaining - 1) + dfs(remaining - 2);
    }
    return dfs(n);
  }

TABULATION (BOTTOM-UP) — USE WHEN...
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Use When:
  □ State dependencies are clear and linear
  □ Want to optimize space (rolling arrays)
  □ All states are needed (dense problem)
  □ Must handle deep recursion (n > 10K)
  □ Loop order is obvious

Pros:
  ✓ No stack overflow (iterative, not recursive)
  ✓ Space optimization is straightforward
  ✓ Execution flow is obvious (loop by loop)
  ✓ Usually slightly faster (no function calls)

Cons:
  ✗ Must initialize all states (even unreachable ones)
  ✗ Loop order can be tricky
  ✗ Code is less intuitive

Example (LC 70 Climbing Stairs):
  function climb(n: number): number {
    if (n === 0) return 0;
    const dp: number[] = new Array(n + 1);
    dp[0] = 1;
    dp[1] = 1;
    for (let i = 2; i <= n; i++) {
      dp[i] = dp[i - 1] + dp[i - 2];
    }
    return dp[n];
  }

DECISION CHART:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Is the problem naturally recursive (has "choose"/"or")?
  ├─ YES: Does recursion exceed depth ~10K?
  │  ├─ NO  → Use MEMOIZATION (cleaner)
  │  └─ YES → Use TABULATION (avoid stack overflow)
  └─ NO: Are state dependencies clear/linear?
     ├─ YES → Use TABULATION (easier to optimize)
     └─ NO  → Use MEMOIZATION (more flexible)

📈 SECTION 6: LINEAR/1D DP PATTERN (Most Common)

Recognition Signals

□ Single parameter: dp[i] depends ONLY on dp[i-1], dp[i-2], etc.
□ Sequential processing: i from 0 to n
□ Answer is dp[n-1] or dp[n]
□ Examples: Fibonacci, Climbing Stairs, House Robber, Coin Change

STATE TRANSITION DIAGRAM:
  dp[0] → dp[1] → dp[2] → ... → dp[n-1] → ANSWER
  (each state computes from previous states)

Template: Pick or Skip Pattern (House Robber)

// LC 198 — House Robber
function rob(nums: number[]): number {
  const n = nums.length;
  if (n === 0) return 0;
  if (n === 1) return nums[0];

  const dp: number[] = new Array(n);
  dp[0] = nums[0]; // Base: rob house 0
  dp[1] = Math.max(nums[0], nums[1]); // Choose best of first two

  // Transition: at house i, either rob it or skip it
  for (let i = 2; i < n; i++) {
    dp[i] = Math.max(
      dp[i - 1],              // Skip house i
      dp[i - 2] + nums[i]     // Rob house i (can't rob i-1)
    );
  }
  return dp[n - 1];
}

// State Transition:
// dp[i] = max(
//   skip house i: dp[i-1],
//   rob house i: dp[i-2] + nums[i]
// )

Template: Multi-Choice Pattern (Climbing Stairs)

// LC 70 — Climbing Stairs (can climb 1 or 2 steps)
function climbStairs(n: number): number {
  const dp: number[] = new Array(n + 1);
  dp[0] = 1; // One way to stay at start
  dp[1] = 1; // One way to reach step 1

  for (let i = 2; i <= n; i++) {
    dp[i] = dp[i - 1] + dp[i - 2]; // Come from step i-1 or i-2
  }
  return dp[n];
}

// State Transition:
// dp[i] = ways to reach step i
//       = sum of ways from all previous steps we can jump from
//       = dp[i-1] + dp[i-2] (for 1 or 2 step jumps)

🔲 SECTION 7: 2D GRID DP

Recognition Signals

□ Two parameters: dp[i][j] for position (i,j) or sequence (i to j)
□ Either a 2D grid problem OR interval optimization
□ For grids: comes from top, left, or diagonal
□ Answer: dp[rows-1][cols-1] or dp[0][n-1]
□ Examples: Unique Paths, LCS, Edit Distance

STATE TRANSITION DIAGRAM (Grid):
  (0,0) → (0,1) → (0,2)
    ↓       ↓       ↓
  (1,0) → (1,1) → (1,2)
    ↓       ↓       ↓
  (2,0) → (2,1) → (2,2)

Template: Unique Paths (Grid Traversal)

// LC 62 — Unique Paths
function uniquePaths(m: number, n: number): number {
  const dp: number[][] = Array.from({ length: m }, () => new Array(n).fill(0));

  // Base: first row and column have 1 path each
  for (let i = 0; i < m; i++) dp[i][0] = 1;
  for (let j = 0; j < n; j++) dp[0][j] = 1;

  // Fill grid: can only come from top or left
  for (let i = 1; i < m; i++) {
    for (let j = 1; j < n; j++) {
      dp[i][j] = dp[i - 1][j] + dp[i][j - 1];
    }
  }
  return dp[m - 1][n - 1];
}

// State Transition:
// dp[i][j] = number of paths to reach (i,j)
//          = dp[i-1][j] (from top) + dp[i][j-1] (from left)

Template: Edit Distance (Sequence Matching)

// LC 72 — Edit Distance
function minDistance(word1: string, word2: string): number {
  const m = word1.length, n = word2.length;
  const dp: number[][] = Array.from({ length: m + 1 }, () => new Array(n + 1).fill(0));

  // Base: distance from empty string
  for (let i = 0; i <= m; i++) dp[i][0] = i;
  for (let j = 0; j <= n; j++) dp[0][j] = j;

  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      if (word1[i - 1] === word2[j - 1]) {
        dp[i][j] = dp[i - 1][j - 1]; // Characters match, no operation needed
      } else {
        dp[i][j] = 1 + Math.min(
          dp[i - 1][j],       // Delete from word1
          dp[i][j - 1],       // Insert into word1
          dp[i - 1][j - 1]    // Replace
        );
      }
    }
  }
  return dp[m][n];
}

// State Transition:
// dp[i][j] = min edits to transform word1[0:i] to word2[0:j]
//          = if match: dp[i-1][j-1]
//          = else: 1 + min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1])

🎒 SECTION 8: KNAPSACK & VARIANTS

8.1 — 0/1 Knapsack (Each item once)

// LC 416 — Partition Equal Subset Sum (variant of 0/1 KP)
// Can we select items that sum to exactly target/2?
function canPartition(nums: number[]): boolean {
  const total = nums.reduce((a, b) => a + b, 0);
  if (total % 2 === 1) return false;
  const target = total / 2;

  // dp[w] = can we make weight exactly w?
  const dp: boolean[] = new Array(target + 1).fill(false);
  dp[0] = true; // Can always make 0

  for (const num of nums) {
    // CRITICAL: Iterate BACKWARD to avoid using same item twice
    for (let w = target; w >= num; w--) {
      dp[w] = dp[w] || dp[w - num];
    }
  }
  return dp[target];
}

// State Transition:
// dp[w] = can we achieve weight w?
//       = dp[w] (don't take item) OR dp[w-item] (take item)

// ⚠️ CRITICAL: Backward loop!
// Forward loop would reuse same item:
//   dp[w] = dp[w] || dp[w-num]
//   But dp[w-num] might have been UPDATED in this iteration
//   using the same item (violating 0/1 constraint)

8.2 — Unbounded Knapsack (Items unlimited)

// LC 322 — Coin Change (unbounded)
// Min coins to make exact amount
function coinChange(coins: number[], amount: number): number {
  const dp: number[] = new Array(amount + 1).fill(Infinity);
  dp[0] = 0; // 0 coins to make 0

  for (let a = 1; a <= amount; a++) {
    for (const coin of coins) {
      if (coin <= a) {
        dp[a] = Math.min(dp[a], dp[a - coin] + 1);
      }
    }
  }
  return dp[amount] === Infinity ? -1 : dp[amount];
}

// State Transition:
// dp[a] = min coins to make amount a
//       = min(dp[a], 1 + dp[a-coin]) for all coins

// ⚠️ KEY DIFFERENCE FROM 0/1 KP:
// Forward loop! This ALLOWS coin reuse.
// dp[a-coin] might use the same coin again, which is valid here.

8.3 — Target Sum with Backtracking + Memo (LC 494)

// LC 494 — Target Sum (Backtracking + DP hybrid)
// How many ways to assign +/- to reach target?
function findTargetSumWays(nums: number[], target: number): number {
  const memo = new Map<string, number>();

  function dfs(index: number, sum: number): number {
    if (index === nums.length) {
      return sum === target ? 1 : 0;
    }

    const key = `${index},${sum}`;
    if (memo.has(key)) return memo.get(key)!;

    // Choice 1: add nums[index]
    const add = dfs(index + 1, sum + nums[index]);

    // Choice 2: subtract nums[index]
    const sub = dfs(index + 1, sum - nums[index]);

    memo.set(key, add + sub);
    return add + sub;
  }

  return dfs(0, 0);
}

// State Transition:
// dfs(i, s) = ways to reach target starting from index i with current sum s
//           = dfs(i+1, s + nums[i]) + dfs(i+1, s - nums[i])
//
// ✅ Memoization key insight: (index, current_sum) can be reached
//    multiple ways — that's why we cache!

One of the most confusing transitions. Here's the exact logic.

THE SPECTRUM:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

PURE BACKTRACKING (No DP needed):
  Pattern: Explore all permutations/combinations, each unique
  Examples: LC 46 (Permutations), LC 51 (N-Queens), LC 22 (Valid Parentheses)
  Tree: NO overlapping nodes
  Performance: O(factorial) or O(2^n) acceptable for small n
  Code: Just recursion, no memoization

BACKTRACKING TURNS INTO DP:
  Pattern: Still recursive exploration, BUT same state reached multiple ways
  Examples: LC 494 (Target Sum), LC 1049 (Last Stone II)
  Tree: OVERLAPPING nodes! Same (index, state) reached via different paths
  Signal: If naive backtracking TLEs → add memo
  Code: Add memoization layer

OBSERVATION (SDE3):
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Both use recursion. The ONLY difference is:
  Pure backtracking: Each state visited once
  Backtracking + memo: Each state visited once PER UNIQUE PATH

Example breakdown (LC 494):
  At index 3, sum=5:
    Path 1: [+1,+2,+3] reaches (3,6)
    Path 2: [+1,+2,+2] reaches (3,5) ← DIFFERENT
    Path 3: [-1,+3,+3] reaches (3,5) ← SAME as Path 2!

  Without memo: Recompute (3,5) twice (wasteful)
  With memo: Compute (3,5) once, reuse (efficient)

DECISION LOGIC:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. Write recursive brute force (backtracking)
2. Does it TLE on expected constraints?
   - NO → You're done (pure backtracking sufficient)
   - YES → Same state is reachable multiple ways → add memoization

Example 2: House Robber (Pick or Skip)

PROBLEM: Rob houses on street. Can't rob adjacent houses.
Max money?

STATE TRANSITION DIAGRAM:
  House[0]=1  House[1]=3  House[2]=2  House[3]=4
    |           |           |           |
  dp[0]=1    dp[1]=3      dp[2]=?     dp[3]=?

  dp[i] = max(
    skip house i → keep dp[i-1],
    rob house i → add house[i] to dp[i-2]
  )

COMPUTATION:
  dp[0] = 1 (rob house 0)
  dp[1] = max(skip=1, rob=3) = 3 (rob house 1 instead)
  dp[2] = max(skip=3, rob=1+2) = 3 (keep skipping house 2)
  dp[3] = max(skip=3, rob=3+4) = 7 (rob houses 0 and 3)

KEY INSIGHT:
  State transition = optimization between two exclusive choices
  This pattern appears in many problems (buy/sell stock, etc.)

Example 3: Edit Distance (2D Transition)

PROBLEM: Transform "cat" → "car"
Min edits (insert/delete/replace)?

STATE TRANSITION DIAGRAM (2D):
        ""   c   a   r
    ""   0   1   2   3
    c    1   0   1   2
    a    2   1   0   1
    t    3   2   1   1

READ AS:
  dp[i][j] = min edits to transform first i chars of "cat" 
             to first j chars of "car"

TRANSITIONS:
  If cat[i-1] == car[j-1]: dp[i][j] = dp[i-1][j-1]
  Else: dp[i][j] = 1 + min(
    dp[i-1][j],     // Delete from cat
    dp[i][j-1],     // Insert into cat
    dp[i-1][j-1]    // Replace
  )

TRACE (cat → car):
  "" → "":  0 edits
  "" → "c": 1 (insert c)
  "" → "ca": 2 (insert c,a)
  "" → "car": 3 (insert c,a,r)
  "c" → "": 1 (delete c)
  "c" → "c": 0 (match!)
  "c" → "ca": 1 (insert a)
  ...
  "cat" → "car": 1 (replace t with r)

KEY INSIGHT:
  2D DP fills a table, not a line
  Decisions come from three neighbors (top, left, diagonal)

BUG #1: Base Case Wrong (Most Common)
❌ WRONG:
  dp[0] = 0
  // But if answer is "ways", dp[0] should be 1!

✅ CORRECT:
  // Trace manually on smallest example
  // dp[0] should be? (count=1 way, value=0, etc.)

BUG #2: Using 0 as "Not Computed" Sentinel
❌ WRONG:
  const dp = new Array(n).fill(0);
  if (!dp[i]) return dfs(i); // Fails if answer is 0!

✅ CORRECT:
  const dp = new Array(n).fill(-1);
  if (dp[i] === -1) return dfs(i);

BUG #3: Loop Bounds Off-by-One
❌ WRONG:
  for (let i = 0; i < n; i++) // Misses dp[n]

✅ CORRECT:
  for (let i = 0; i <= n; i++) // Check problem carefully

BUG #4: Backward vs Forward Loop (Knapsack)
❌ WRONG (0/1 KP):
  for (const item of items) {
    for (let w = 0; w <= capacity; w++) { // Forward = reuses item!
      dp[w] = max(dp[w], dp[w - item] + value);
    }
  }

✅ CORRECT:
  for (const item of items) {
    for (let w = capacity; w >= item; w--) { // Backward = 0/1
      dp[w] = max(dp[w], dp[w - item] + value);
    }
  }

BUG #5: 2D Array Reference Sharing
❌ WRONG:
  const grid = new Array(n).fill(new Array(m).fill(0));
  grid[0][0] = 1; // Modifies ALL rows!

✅ CORRECT:
  const grid = Array.from({ length: n }, () => new Array(m).fill(0));

BUG #6: Map Key Collision (String Encoding)
❌ WRONG:
  const key = `${i}${j}`; // "1,23" and "12,3" both → "123"

✅ CORRECT:
  const key = `${i},${j}`; // Always use non-numeric separator

BUG #7: Forgot to Return Memoized Result
❌ WRONG:
  memo[i] = dfs(i);
  return dfs(i); // Computes again!

✅ CORRECT:
  if (memo[i] !== -1) return memo[i];
  memo[i] = dfs(i);
  return memo[i];

BUG #8: Stack Overflow on Deep Recursion
❌ WRONG: Recursive DP with n=100K
  function dfs(i) { return dfs(i+1) + ...; } // Stack overflow!

✅ CORRECT: Use iterative tabulation for large n

BUG #9: Negative Indices (Python habit)
❌ WRONG: Copied from Python
  if (i > 0) dp[i-1] // Fine
  dp[-1] // Doesn't work in JS, returns undefined

✅ CORRECT: Always use (i-1) or offset indices

BUG #10: Initialization Optimism
❌ WRONG:
  const dp = [];
  // Forgot to initialize dp[0], dp[1], etc.

✅ CORRECT:
  const dp = new Array(n).fill(-1); // or appropriate default

✨ FINAL WISDOM

DP isn't about memorizing patterns. It's about recognizing: 1. Can this be solved recursively? (If no → not DP) 2. Do subproblems repeat? (If no → backtracking only) 3. Can I cache those subproblems? (If yes → add memo) Master these three questions. Every DP problem is a variation on this theme. You've got this. 🚀
